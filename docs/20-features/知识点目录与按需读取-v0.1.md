# 知识点目录与按需读取 · v0.1

> 配套：[`营小商-MVP-v2.0.md`](../00-mvp/营小商-MVP-v2.0.md) §3、§5；[`营小商-现状不足与可借鉴-v0.1.md`](../00-mvp/营小商-现状不足与可借鉴-v0.1.md)。
> 本文回答三件事：**为什么退掉材料预取**、**做完之后一轮是什么样**、**怎么验收**。

---

## 1. 为什么做

原来的 `prefetchMaterial` 每轮做四件事：

1. 按学生这句话，代码挑最多 6 个知识点；
2. 每个知识点取最多 2 段教材原文；
3. 把定义、例子、原文拼进 system 的「已经备好的材料」；
4. 把这些内容标成「本轮已读」。

问题不在“多给了材料”，在**给材料的是代码，不是模型**：

| 问题 | 具体表现 | 后果 |
|---|---|---|
| 代码替模型选材料 | 学生问「谢谢」「那学习呢」，代码也会预取 6 个知识点 | 上下文被无关材料占据，模型注意力被带偏 |
| 预取内容不能用工具重读 | `createToolContext` 把预取 key 放进 `seed`，`read_material` 看到 `firstTime=false`，回「本轮已经读过」 | 模型想核对原文时拿不到，只能靠 system 里那一次 |
| trace 虚高 | `prefetchMaterial` 直接写 `reads.kps` / `reads.blocks` | 看起来「读了 6 个知识点」，其实模型没选过 |
| 和产品口径冲突 | MVP 写的是「模型看着工具清单，自己决定先干什么」 | 代码先替它决定了一半 |

这和 DSH 的形状相反：DSH 的 system prompt 只放稳定指令与运行时事实；材料由工具按需读。`agent-instructions` 是唯一预取的东西，因为它是持久工作区指令，而且有 `maxBytes` 预算，不是业务材料。

## 2. 做完是什么

### 2.1 system 里只有目录

`environment()` 生成「本章知识点目录」，每个知识点一行：

```text
## 本章知识点目录（41 个）
只用于选材料，不是原文。讲概念、案例、新闻前先调用 read_kp / read_material / read_textbook 读正文；不要拿目录当引用。

- 消费者（消费者与消费者市场）：为生活消费而购买和使用产品或服务的个人和家庭
- 消费者行为（消费者行为）：消费者为满足需要而进行的购买、使用、处置活动
...
```

- 目录只放 `name` + 小节 + 一句话定义（截 60 字）。
- 不放别名、教材例子、非例子、原文段落。
- 目录不是引用来源；引用必须来自读工具返回的原文。

### 2.2 正文由模型读

| 要什么 | 工具 |
|---|---|
| 一个知识点的完整定义、别名、例子、非例子 | `read_kp` |
| 1–4 个知识点的定义 + 教材原文 | `read_material` |
| 更宽的教材原文 | `read_textbook` |
| 新闻候选与正文 | `search_news` → `read_news` |

工具返回的内容进对话历史，`turn.reads` 由工具自己记账，`citations` 由工具自己写；没有预取，不再有“假已读”。

### 2.3 提示词里的硬规则

`packages/agent/agents/mentor.md` 的「取材料」一节写死：

- 目录只有名称和一句话，**不是原文，不能当引用**；
- 讲概念、讲案例、分析新闻之前，必须先取正文；
- 没取到材料就说资料不足，不要用目录或常识补成「教材原文」。

### 2.4 一轮的实际形状

```text
学生说一句话
   ↓
system：身份 + 当前环境 + 知识点目录（没有正文）
   ↓
模型选材料：read_kp / read_material / read_textbook / search_news
   ↓
工具返回正文，进入 messages
   ↓
模型回答或写产物；引用来自刚才读到的原文
```

比原来多一次工具往返；换来的是材料由模型选、trace 真实、目录不会冒充原文。

## 3. 接口契约

目录和工具的分工：

| 层 | 负责 | 不负责 |
|---|---|---|
| system 目录 | 告诉模型“本章有哪些知识点、一句话是什么” | 不提供可引用原文 |
| `read_kp` / `read_material` / `read_textbook` | 提供定义、例子、原文；写 `reads` 与 `citations` | 不判断学生要不要产物 |
| `search_news` / `read_news` | 检索新闻候选、读正文；写 `reads.news` 与引用 | 不预取新闻正文 |
| `list_chapter_kps` | 兜底：要一次看全量定义时用 | 不是主路径 |

目录的边界：

- 只列当前章节的知识点；换章后重建。
- 定义截 60 字，超出用 `…`；不截断 surrogate pair。
- 目录本身不计入 `citations`，也不写 `reads.kps`；只有真正调用读工具才记账。

## 4. 与 DSH 的对应

| 我们的做法 | DSH 对应 |
|---|---|
| system 目录只有 `name` + 一句话 | `@deepseek-ai/dsh-tool-skill` 的会话目录：只放 name + 有长度上限的 description，正文用 `skill` 工具加载 |
| 目录明确写“摘要不是正文，必须先加载” | skill 目录模板的 “This catalog contains summaries only; do not infer or follow a skill's instructions until it has been loaded” |
| 正文由读工具返回，进对话历史 | MCP resources：`list_mcp_resources` / `read_mcp_resource`，内容按需读，文本进对话历史 |
| 不预取业务材料 | DSH 的 system prompt 只放稳定指令与运行时事实；`agent-instructions` 只预取持久工作区指令，且有 byte 预算 |

没有引入 MCP resources 协议。我们的 `read_*` 工具已经是领域化的“资源读取”，再套一层 URI、分页、服务器名只会增加模型的选择成本。

## 5. 验收

真实服务，不写假断言。

| # | 场景 | 应该看到 |
|---|---|---|
| 1 | 「用第4章讲一下消费者」 | 模型先调 `read_kp` 或 `read_material`；回复引用的定义/原文来自工具结果；`trace.reads.kps` 只包含真正读过的 |
| 2 | 「用第4章分析最新新闻」 | 模型先 `search_news`，再 `read_news`；`trace.reads.news ≥ 1`；目录里的知识点不冒充新闻 |
| 3 | 「给我出3道消费者情境题」 | 模型读知识点/题库依据后再出题；`question_set` 正常 |
| 4 | 连续两轮追问 | 第二轮能接上第一轮（历史在 messages），不重复读同一材料 |
| 5 | 目录体积 | 目录约 2–3k 字（41 个知识点 × 名称 + 一句话）；不再含 6 个知识点的整段原文。`systemChars` 不一定下降，但可引用正文已移出 system |

---

## 6. 不做什么

- 不引入 MCP resources / URI 协议。
- 不做向量检索或自动 rerank；目录是本章全量，模型自己选。
- 不预取新闻正文，也不在 system 里放新闻标题列表；新闻只走 `search_news` / `read_news`。
- 不为目录单独做一套 schema 或数据库表；它就是 `environment()` 的一段文本。
- 不改产物通道、不改出题结构、不改历史消息形状。
