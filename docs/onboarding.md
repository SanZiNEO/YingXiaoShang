# 营小商 · 新人入门

> 看完这一页你就能上手。深的东西不用现在读，先知道「这东西为谁做、长什么样、怎么动」。
> 最后更新：2026-11-03

---

## 一、这是什么

**营小商**是给市场营销专业学生用的桌面 AI 助教。学生像聊天一样问问题，
它会调用课程知识库、真实新闻和教材原文来回答；要成果时给一份能带走的页面或题目集。

一个学生，一个窗口，一个对话者。没有角色切换，没有「专家会议」。

## 二、为谁做，做成什么样算好

**使用者**：市场营销课的学生（当前是任课老师带的班级）与任课老师。

**老师的诉求（原话转述）**：

| 诉求 | 意味着什么 |
|---|---|
| 学生问问题能讲清楚，不是百科摘抄 | 回答要有判据、有取舍，能指出「这里容易错」 |
| 能用真实案例练判断 | 案例必须可回溯到原文，不许编 |
| 老师能交付、能带走 | 页面/题目集是文件，不是聊天记录 |
| 学习情况要看得到 | 成长卡要有学生真实作答作证据，不能拿 AI 的话当证据 |
| 手机上也能用 | 未做。当前只有桌面端，见 `plans/0.2.0/pending-discussions.md` P-6 |

**理想效果**（能做到这五条就算成）：

1. 学生问一个概念，30 秒内拿到解释 + 一个检验理解的问题。
2. 学生问一个案例，答案里的每个引文都能在原文里找到。
3. 学生要成果，拿走一个文件，且内容与聊天里说的一致。
4. 学生出题做题，交卷能判，判的就是屏幕上那份题。
5. 对话越用越懂这个学生，且学生自己的话优先级最高。

**明确不做**：代写作业、编造数据、假装读过没读的材料、把 AI 生成内容当学生能力证据。

## 三、架构

### 3.1 现在（0.1.x）

```text
Electron 渲染层 (React)
    │  IPC: learning:chat / chat-event
主进程 (Node)
    │  会话归属、设置、事件转发
Agent 服务 (packages/agent)
    │  team.ts 装配 → tool-loop.ts 循环 → 9 个领域工具
数据 (SQLite + 文件)
    课程知识点 / 新闻 / 题库 / 产物 / 学情
```

关键约束：

- **一个说话人**：只有 `mentor.md` 这套人格对学生说话；工具、记录器都不上屏。
- **按需取材**：system 里只有目录和索引，正文必须由工具取，目录不能冒充原文。
- **判据进 skill**：案例怎么算讲透、题怎么算合规，是 `skills/` 里 markdown 的判据，不是代码分支。
- **不预设轮次**（**尚未做到**）：目标是不设「第 N 轮必须回答」，但当前代码里是
  `team.ts:210` 写死 `maxRounds: 10`，用完还有第 11 轮强制收口（审计 F03）。
  这一条随原生 loop 切换一起删除，**不要把它当成现状**——上一轮就是因为误判这一点走了弯路。

### 3.2 正在做（0.2.0）

把上面「循环 + 工具调度 + prompt 装配 + 上下文压缩」换成 DSH 原生运行时，
自己只留业务：课程/新闻/证据读取、题目与产物提交、学情记忆、界面。

```text
Electron 渲染层 ──IPC──▶ 主进程（薄）
                            │
                     DSH 原生运行时
              (loop / session / tools / skill / compaction)
                            │
                     营小商的领域工具
                            │
                    课程 · 新闻 · 题库 · 产物 · 学情
```

为什么换：审计发现的问题（等待无边界、文字撤回、工具谎报成功、题目不落题库、记忆断链）
有 7 条是 P0，全都长在自研循环与自研调度上。修一遍等于重写一遍，不如直接用原生件。

计划与派单：`plans/0.2.0/`。

## 五、思路（三条，够用很久）

1. **能复用就别自研**。上一轮最大的浪费是自己写了一套「相似但不完整」的运行时。
   DSH 是 MIT，直接拿来用，先全量堆上去，再砍不要的。
2. **判断放提示词，能力放工具，判据放 skill**。写新能力前先问：这是判断、能力，还是判据？
   答不出来就别写。
3. **不要拿计数当完成判据**。「跑了 10 轮」「调了 8 个工具」不代表任务做完了；
   工具有没有真拿到材料、写有没有真落库，才是。

## 六、重建计划（学长定的，0.2.0）

这条路子是学长在他自己的模组项目里跑通后才交给我们的，不是拍脑袋。

### 6.1 三层文档在管什么

| 层 | 文件 | 管什么 | 谁来写 |
|---|---|---|---|
| 方向 | `docs/agent-runtime-audit-and-rebuild-guide.md` | 现状为什么不行、改成什么、为什么不选别的 | 人（学长） |
| 计划 | `plans/0.2.0/README.md` | 分几轮、每轮什么主题、当前到哪 | 人 + AI |
| 派单 | `plans/0.2.0/ROUND-X-MAP.md` | 这一轮做哪几个任务、每个怎么验 | AI 建图后写 |

配套三份：`implementation-progress.md`（进度真源）、`pending-discussions.md`（要人拍板的）、
`主代理-轮次任务模板.md`（怎么派单、怎么验收、什么不许问）。

### 6.2 六轮

| 轮次 | 主题 | 一句话 |
|---|---|---|
| **A** | 原生组合与兼容边界 | 核实版本、协议、session、资源根，产出「挂什么、怎么挂」的结论 |
| **B** | 最小原生链路 | 把 DSH 原生 loop 在 Electron 里跑通一次真实对话 |
| **C** | 接业务内容 | 提示词、skill、课程/新闻/证据读取、产物与题目提交 |
| **D** | context 与桌面视图 | skill 目录、上下文压缩、事件到界面、不撤字、可取消 |
| **E** | 单次切换与清理 | 删旧循环，更新受影响的 R 文档，打包资源 |
| **F** | 验收 | 场景矩阵、性能分项、故障注入、安装包 |

**并行一条轨道 0（交付）**：给老师/同学用的版本，不等重建。重建几周，不能拿它当借口拖着不发。

### 6.3 每一轮怎么跑

```text
读 ROUND-X-MAP  →  建图（真实文件+符号，回填 MAP）  →  拆 todo
   →  派子代理调查/执行（五要素：目标/材料/交付物/验收/回报）
   →  主代理独立复跑验收  →  回填 progress  →  下一小轮
```

三条硬规矩：

1. **主代理不写业务代码**，只建图、拆单、验收。
2. **子代理不能反问**——信息不足是派单方的责任，补齐再派。
3. **该自己判断的别外包**：「删旧格式还是留兼容层」这类问题有现成答案，不要拿去问人。

## 七、协作工作流

```text
方向稿  →  拆轮次（A–F）  →  每轮一份 ROUND-X-MAP（目标/材料/交付物/验收）
        →  主代理建图  →  派子代理调查/执行  →  主代理独立验收  →  回填进度
```

- **主代理不写业务代码**，只建图、拆单、验收。派单协议见
  `plans/0.2.0/主代理-轮次任务模板.md`。
- 每开一轮，把「模板 + ROUND-X-MAP」一起给 AI，它就能执行已定好的计划。
- 冲突**不许自行取舍**，问人，结论回填 `pending-discussions.md`。
- 进度写进 `implementation-progress.md`，不攒到最后。

**新人第一天该做的三件事**：

1. 读 `docs/principles/single-agent.md`（唯一设计原则，很短）。
2. 读 `docs/README.md` 的权威顺序，知道冲突时听谁的。
3. 打开 `plans/0.2.0/README.md`，看当前轮到哪一轮，认领一个小轮。

## 八、跑起来

```bash
pnpm install                          # 注意：本机会卡在 851/851，见「已知坑」
pnpm run db:seed                      # 灌课程库
pnpm run db:seed:student              # 灌示例学生
pnpm run dev:desktop                  # 起桌面端
```

配置 Key：`%APPDATA%\营小商\settings.json`，三行 JSON：

```json
{ "apiKey": "sk-...", "model": "deepseek-chat" }
```

**必须存成不带 BOM 的 UTF-8**。PowerShell 的 `Set-Content -Encoding utf8` 会写 BOM，
旧版本会因此报 `DEEPSEEK_API_KEY is not configured`，而文件里明明有 Key。

## 九、已知坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `pnpm install` 卡住 | 851/851 后 `.bin` 不生成 | 优先用仓库里已装好的依赖跑验证；不要把重装当第一步 |
| 改默认值没生效 | 改了 `tool-loop` 默认轮次，行为不变 | 上层有写死参数（`team.ts`），先 `grep` 全部调用点 |
| 判据错时工具很自信 | 校验脚本误报 30 条 | 写检查器先自检：拿已知错误的数据跑一遍，确认它真能报错 |
| 文档行号漂移 | 需求文档指向的行号不存在了 | `python tools/verify-doc-refs.py` |
| 引文对不上原文 | 案例里的话在原文找不到 | `python tools/verify-case-quotes.py` |

## 十、名词

| 词 | 意思 |
|---|---|
| 知识点（kp） | 教材里一个可独立讲清的概念，含短定义 + 教材原文 |
| 判据（skill） | 一段 markdown，写「什么算讲透/合规」，不是代码 |
| 产物（artifact） | 学生能带走的文件：页面、题目集 |
| 轮次（round） | 重建计划里的一个阶段，A–F |
| 主代理 | 负责建图/拆单/验收的角色，不写业务代码 |
