## 一、这个项目是什么

### 60 秒版

一个**装在自己电脑上的 AI 助教**，名字叫「营小商」。

学生打开它，可以：

- 问市场营销课的问题，它会**引用教材原文**回答（不是瞎编）
- 让它出练习题，在界面上答题、交卷、看解析
- 用真实企业案例做分析练习
- 它会记住每个学生问到哪、哪里弱

它**不是网页**，是一个双击就能打开的桌面程序（Windows）。
不需要联网也能查课程内容；只有查「最新新闻」时才联网。

### 为什么做这个

市场营销这门课有两个老问题：

1. **教材内容多，学生不知道哪里不会**。老师一个人对几十个学生，没法逐个答疑。
2. **案例教学依赖老师现场讲**。学生课后想练，没有材料、没有人反馈。

这个工具想解决的是：**让每个学生都有一个「随时能问、会引用教材、会出题考你」的陪练**，
把老师的精力省下来做只有老师能做的事（判断、点评、给方向）。

### 给谁用

- **主要用户**：上市场营销课的学生
- **次要用户**：任课老师（要看学生进度，这部分**还没做**）
- **决策人**：魏老师（课程负责人）

### 三条硬规矩

1. **任何学生能看到的地方，都不出现学校名字**，只叫「营小商」。
2. **面向非技术用户**：解压、双击、就能用。不能要求装环境、不能要求改配置。
3. **不能依赖文件编码和系统语言设置**（这条踩过两次坑，见第五节）。

## 二、现在能干什么（真实效果，都有实测）

| 能力 | 学生的感受 | 实测数据 |
|---|---|---|
| 双击就能用 | 解压 → 双击 → 出现窗口 | 42 个文件、158MB 的压缩包 |
| 聊天问答 | 打字就有回答，字是一个个出来的 | 连问 8 轮，每轮 4–6 秒 |
| 引用教材 | 回答下面能看到「依据：第 X 章 XX」 | 点开能看到原文 |
| 查课程知识 | 问概念，它翻教材给你讲 | 一次查 3 个概念 7.2 秒（原来 30 秒） |
| 出题 + 答题 + 交卷 | 出 20 道题，做完交卷，立刻判分 | 真实学生 20 题实测通过 |
| 记住你的进度 | 下次打开知道你学到哪、哪里弱 | 进度从 0/8 变成 8/8 |
| 查最新新闻 | 本地没有就去网上找 | 搜索 0.5 秒，入库 1.9 秒（原来 3 分钟） |
| 能中途停 | 说错了可以点「停止」 | 46–141 毫秒内真停 |
| 出错说人话 | 不是一堆英文报错 | 断网/密钥错/余额不足/磁盘满都有中文解释 |
| 装坏了能发现 | 提示"重新解压一次" | 启动时自检文件完整性 |

### 现在**还**不能干什么（重要，别误会）

- ❌ **老师看不到学生数据**。老师端是 **0 行代码**。现在只有学生自己能看到自己的档案。
- ❌ **不能手机用**。只有 Windows 桌面版。
- ❌ **不能一个班同时用**。每台电脑各跑各的，数据不互通。
- ❌ **题目质量没有人工把关过**。AI 出的题可能偏简单或问法怪，需要老师抽检。

## 三、系统长什么样（不用懂代码，但要懂结构）

### 3.1 三层

```
┌─────────────────────────────────────────┐
│  外壳（学生看到的部分）                   │
│  窗口、聊天框、题目卡片、进度条            │
│  → apps/desktop                         │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  大脑（AI 助教）                          │
│  决定「要不要查资料」「查哪个」「怎么答」   │
│  → packages/agent                        │
└─────────────────┬───────────────────────┘
                  │
┌─────────────────▼───────────────────────┐
│  资料库（本地数据）                       │
│  课程知识点、教材原文、新闻、学生档案      │
│  → packages/{knowledge,news,db,...}      │
│  → 一个文件：learning.db                  │
└─────────────────────────────────────────┘
```

### 3.2 数据存在哪（出问题先看这两处）

| 什么东西 | 在哪 | 说明 |
|---|---|---|
| 学生学情、题目、答题记录 | `C:\Users\<你的用户名>\.learning-agent\data\learning.db` | 一个文件装全部。**备份就是复制这个文件** |
| API 密钥、模型设置 | `%APPDATA%\营小商\settings.json` | 里面有付费密钥，**别发给别人、别截图** |
| 课程知识点、教材 | 打包在程序内部 | 改内容要重新打包 |

> ⚠️ 注意：数据**不在** `%APPDATA%\营小商\`，那只是配置。很多人会搞混。

### 3.3 三条设计原则（这是前任踩坑总结出来的）

1. **判断放提示词，能力放工具，判据放 skill**
   - 「该不该联网查新闻」= 判断 → 写在提示词里
   - 「怎么查」= 能力 → 写成一个工具（`search_news`）
   - 「什么样的新闻算相关」= 判据 → 写在 skill 里
   - 混在一起就会变成"改一句话要动三处"

2. **不自己造 AI 的「思考循环」，用现成的**
   - 前任的审计报告明确指出：自己写的循环有固定轮次上限，会导致"复杂问题必然答不完"
   - 现在用运行时原生能力，**不设轮次上限**

3. **每次修复都必须先有一个「会失败的测试」**
   - 先写断言 → 跑一遍看到它**红**（失败）→ 再改代码 → 看到它**绿**（通过）
   - 没有这一步，你永远不知道自己是"修好了"还是"碰巧没报错"

### 3.4 已经做过的重要决定（别再推翻）

| 决定 | 为什么 |
|---|---|
| 用 exe 启动器，不用 bat 脚本 | bat 依赖系统编码，中文路径会乱码（踩过） |
| 历史对话要压缩 | 不压缩会越聊越慢、越聊越贵 |
| 联网搜索是自动的，不让 AI 自己决定 | 之前 AI 经常忘记开，学生就问不到新闻 |
| 查新闻不爬网页 | 爬网页 30 秒/篇，5 篇就三分钟。搜索 API 自带正文，0.5 秒 |
| 先做「学生能走完一轮」，再做老师端 | 学生用不下去，老师端做得再漂亮也没数据 |

## 四、不同环节的工作流（照着做）

### 4.1 第一次把项目跑起来

> 你机器上只有 pi。要跑这个项目，需要先装 3 个东西。**让 pi 帮你装**，你只要说：

```
我要在这台电脑上跑一个 Electron + TypeScript 的项目，但我什么开发工具都没装。
请一步一步带我装 Node.js LTS、Git for Windows、pnpm，每装完一个告诉我怎么验证成功。
```

需要装的东西和下载地址：

| 工具 | 干什么用 | 下载 |
|---|---|---|
| Node.js (LTS) | 跑 JavaScript 的引擎 | https://nodejs.org/zh-cn |
| Git for Windows | 版本管理 + 命令行 | https://git-scm.com/download/win |
| pnpm | 装项目依赖 | 装完 Node 后在终端运行 `npm i -g pnpm` |

装完验证（在终端里逐条敲，都应打印版本号）：

```powershell
node -v
git --version
pnpm -v
```

然后拿代码：

```powershell
cd G:\市场营销ai
git clone <仓库地址> learning-agent
cd learning-agent
pnpm install
```

> ⚠️ **`pnpm install` 在这台机器上曾经卡在 851/851**。如果真的卡住超过 10 分钟，
> 让 pi 看 `plans/0.2.0/HANDOFF.md`，里面记了替代路线（不用装依赖也能构建）。

启动：

```powershell
cd apps\desktop
pnpm dev
```

第一次启动会要求填 API 密钥（DeepSeek）。**密钥找魏老师或问项目负责人要，不要自己乱申请**。

### 4.2 改一个功能（标准流程，别跳步）

这是整个项目最重要的工作流。**每一步都不能省**：

```
① 说清楚要改什么
   对 pi 说：「学生反馈 X。我怀疑是 Y。请先看代码确认，不要直接改。」

② 先写一个「会失败的测试」
   对 pi 说：「先写断言，让它在现在的代码上失败。我要看到它红。」
   ⚠️ 这一步是防"假修复"的。没有红过，就不算修好。

③ 改代码

④ 跑测试，要看到绿
   scripts\ 目录下每一条 verify-*.ts 都是一个测试

⑤ 让另一个 AI 独立复核
   ⚠️ 不要让写代码的那个 AI 自己检查自己，它一定会说"没问题"
   对 pi 说：「派一个独立的复核代理，只给它改动和需求，不给我的结论，让它找错。」

⑥ 复核提的问题，改到过

⑦ 打包、真机试、提交
```

**为什么这么麻烦**：这个项目已经出现过两次「以为修好了其实没有」——
一次是停止按钮"假停"，一次是测试"假变红"。都是自测骗自己的结果。

### 4.3 打包，发给老师

> 老师只会做一件事：解压、双击。所以包必须自己长好。

```powershell
# 1. 构建界面和主进程
cd apps\desktop
pnpm build

# 2. 把构建结果塞进 asar（Electron 的打包文件）
#    ⚠️ 必须整目录替换，不能只覆盖——否则会残留旧文件
# 3. 压缩成 zip，最外层文件夹必须叫「营小商」
```

**打完包必须做三件事验证**（少一件都算没打）：

1. 解压后 `grep` 一个只有新版本才有的字符串 → 确认新代码真的进去了
2. 双击 exe，看窗口标题是不是「营小商」→ 确认能启动
3. 看有没有报错弹窗 → 确认没有启动失败

> 现在这个流程是我（前任 AI）手工跑的。**让 pi 把它写成一个脚本**，是接手后值得做的第一件技术活。

### 4.4 提交代码到 GitHub

```powershell
cd G:\市场营销ai\learning-agent
git add -A
git commit -m "一句话说清改了什么、为什么"
git push origin main
```

> ⚠️ **这台机器有个坑**：系统里配了一个失效的代理（`127.0.0.1:10809`），
> 代理没开的时候 `push` 会失败并提示 `Failed to connect`。
> 解决办法是绕开代理直连 GitHub 的 IP（`http.curloptResolve`），
> 具体命令在 `plans/0.2.0/HANDOFF.md`。**让 pi 帮你处理，别自己瞎试。**

### 4.5 学生报了一个问题，怎么办

按这个顺序问，不要一上来就说"我改"：

```
1. 你当时在做什么？（问问题？做题？交卷？）
2. 屏幕上出现了什么？（截图）
3. 是一直这样，还是偶尔？
4. 关掉重开还这样吗？
```

然后判断：

| 情况 | 处理 |
|---|---|
| 数据错了、卡死、白屏 | **P0，当天修** |
| 答案不对、明显误导、假装在做事 | **P1，本周修** |
| 慢、丑、不方便 | **P2，记下来攒着** |

> P0/P1/P2 是**紧急度**，不是功能清单。看到"P2"不要以为是要做的事。

### 4.6 想加一个新闻源

新闻源都在 `services/news-crawler-py/src/news_crawler/sources/`，一源一个文件，现在注册了 50 个、启用 46 个。
加一个新的不是"写一套爬虫"，是"照着现有格式加一个自注册适配器"：

```
对 ai 说：「我想加一个营销行业新闻源，网址是 XXX。
请参照 services/news-crawler-py/src/news_crawler/sources/ 里的源，加一个
DESCRIPTOR + ADAPTER，并在 live_check 里验证能抓到内容。」
```

⚠️ **不要另写一套爬虫系统**。不要往 `packages/news` 里加源适配器；TS 那边只是 Python 服务的 HTTP 客户端，加源只改 Python 的 `sources/<id>.py`。

### 4.7 想改课程知识点/教材内容

内容不是写在代码里的，是通过 `pipeline/` 里的脚本灌进数据库的。
**改之前一定要备份 `learning.db`**。

> 这块最脆弱。动之前让 pi 先给你一份"改之前长什么样"的记录。

### 4.8 想换模型或换密钥

改 `%APPDATA%\营小商\settings.json`。
⚠️ 这个文件曾经出过 BOM 头导致读取失败的问题，**用记事本另存为 UTF-8 无 BOM**，
或者干脆让 pi 用代码改。

## 五、踩过的坑（这一节最值钱）

按「现象」查。每条都是真金白银试出来的。

### 5.1 中文乱码

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 用 bat 脚本启动，中文路径变乱码 | bat 受系统代码页影响 | **用 exe 启动器**，不要用 bat |
| 读文档显示一堆问号和方块 | 文件是 GBK 编码，工具按 UTF-8 读 | Git Bash 里用 `cat 文件 \| iconv -f GBK -t UTF-8` |
| Python 脚本打印中文报错 | 控制台编码 | 运行前设 `PYTHONUTF8=1` |
| 配置文件读不出来 | 文件开头有 BOM 头（看不见的3个字节） | 存成「UTF-8 无 BOM」 |

### 5.2 「改好了」其实没改好

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点停止按钮，等半天才停 | 界面以为停了，实际请求还在跑 | 要看**毫秒数**，不能只看按钮变灰 |
| 测试全绿，但功能是坏的 | 测试写得太松，改坏了也不会红 | **故意把关键代码改成恒假，看测试会不会红** |
| 改了个常量，测试没反应 | 那个常量根本没被用到 | 先确认这个数字真的在生效路径上 |

> **这是最容易骗自己的地方**：AI 会说"已修复，测试通过"，
> 但如果测试本身是坏的，这句话就是假的。**必须做变红实验。**

### 5.3 越用越慢

| 现象 | 真正原因 | 怎么办 |
|---|---|---|
| 问的问题越长，回答越慢 | ❌ 错。实测长度和耗时无关 | 别往这个方向查 |
| 一查资料就特别慢 | 每查一次概念就调用一次模型，10 次就是 10 个 10 秒 | **一次读齐**：批量查，别一个个查 |
| 查一条新闻卡 3 分钟 | 搜索完还去爬网页，30 秒/篇 × 5 篇 | **不爬网页**，用搜索 API 自带正文 |
| 聊了 10 轮以后变慢 | 历史对话全带上去了 | **压缩历史**：最近 3 轮逐字，更早的摘要 |

### 5.4 AI 相关的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一直报 `transport failed` | 消息少了 `role:'user'` 标记 | 用户消息必须带角色标记，缺了会报这个误导性错误 |
| AI 该联网却不联网 | 它忘了传参数 | **别依赖它记得**，改成代码自动判断 |
| AI 拿旧新闻说成最新 | 没告诉它本地库最新到哪天 | 工具结果里**写明日期** |
| 交卷失败，判题说找不到题目 | 题目只存在界面里，没进题库表 | **出题时就登记进题库** |
| 多选题永远判错 | 题型名字不统一（`multiple_choice` vs `多选`） | 加一个统一转换函数 |

### 5.5 打包和交付的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 新包里还是旧界面 | 只覆盖了部分文件，旧文件残留 | **整目录替换** |
| 双击 exe 没反应也没有窗口 | 启动就崩了，但没人接住错误 | 启动失败必须弹窗告诉用户怎么办 |
| 换了台电脑打不开 | 缺配置/被杀毒软件拦 | 必须在一台干净电脑上试过 |
| 学生解压后少了文件 | 解压工具问题/下载不全 | 启动时自检文件完整性 |

### 5.6 环境和工具的坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `git push` 报 `Failed to connect to 127.0.0.1` | 系统配了失效代理 | 绕开代理直连 IP（见 HANDOFF.md） |
| `pnpm install` 卡在 851/851 | 依赖源问题 | 有替代路线，不装依赖也能构建 |
| 命令跑了半天没动静 | 前台跑了服务器/监听进程 | 后台跑 + 写日志，然后看日志 |

## 六、红线（绝对不能做的事）

1. **不要把 API 密钥写进代码、写进文档、发到群里、截图**
2. **不要在面向学生的界面里出现学校名字**
3. **不要在学生真实数据上做实验**。要试先备份 `learning.db`
4. **不要跳过"先让测试变红"这一步**
5. **不要让写代码的 AI 自己复核自己的代码**
6. **不要一次改 5 个地方**。一次 1–2 件，改完验证完再下一件
7. **不要删 `plans/0.2.0/` 里的文档**。那是判断依据，删了就不知道当初为什么这么设计

| 仓库 / repo | 装这个项目所有文件的那个文件夹，带历史记录 |

| push | 把存档传到 GitHub（云端），别人才能看到 |
| 依赖 / install | 这个项目要用别人写好的零件，得先下载下来 |
| 构建 / build | 把源代码"编译"成能直接跑的程序 |
| 打包 | 把程序 + 运行环境压成一个能发给别人的压缩包 |
| 断言 / 测试 | 一段自动检查"这里应该等于 5"的代码，不等于就报错 |
| 变红 / 变绿 | 测试失败叫红，通过叫绿 |
| 提示词 | 给 AI 的说明书，告诉它该怎么做事、什么不能做 |
| 工具 / tool | 给 AI 加的一个"能力"，比如"能查新闻" |
| M1 / M2 / M3 | 三个阶段：一个人能用 / 一个班能发 / 多端 |
| P0 / P1 / P2 | 紧急度：会炸 / 明显不对 / 可以等等 |

## 十、每周怎么安排

```
周一   看反馈，决定这周做什么（最多 2 件）
周二三 改代码 + 自己测 + 让另一个 AI 复核
周四   打包，在一台干净电脑试
周五   找魏老师 10 分钟，确认她关心的事有进展
周末   休息
```

**判断自己这周有没有进展，只看一件事**：
有没有一个**真实的人**（学生或老师）因为这周的改动，少卡了一次。

## 十一、附：上手第一周的建议动作

如果你完全不知道从哪开始，按这个顺序：

**第 1 天**：让 pi 读完这份文件 + `plans/0.2.0/ROADMAP.md`，
然后让它用大白话给你讲一遍这个项目。**你听，不要它改任何东西。**

**第 2 天**：让 pi 带你在这台电脑上把项目跑起来（`pnpm dev`）。
跑不起来也没关系，卡在哪就记下来，这是最有价值的反馈。

**第 3 天**：双击现有的 `营小商-双击即用-1105g.zip`，自己当学生用 30 分钟：
问 3 个问题、让它出 5 道题、交卷、看档案。**记下你觉得别扭的每一处。**

**第 4 天**：把那 30 分钟的记录给 pi，让它判断哪些是 bug、哪些是设计问题。

**第 5 天**：挑最小的一个问题，走完一次完整流程
（写断言 → 变红 → 改 → 变绿 → 复核 → 打包 → 提交）。

**第一周不要碰**：老师端、手机端、新闻爬虫、数据库结构。
