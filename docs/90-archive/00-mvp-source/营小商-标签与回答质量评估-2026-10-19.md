# 营小商：标签与回答质量评估

> 日期：2026-10-19  
> 范围：只评估，不改代码。  
> 触发问题：用户觉得系统“还是硬编码”“tags 是英文”“匹配度不高”“每次输出都三点”，并与另一个系统回答同一问题作对比。

---

## 0. 结论摘要

用户的直觉基本成立，但要拆成三件事：

1. **教材段落 tags 实际上没有生成。** `content_blocks` 有 744 段（ch04 47 段），但 `content_tags` 是 **0 条**。设计里有表、有类型、有写入方法，但没有 pipeline 真正写它。
2. **新闻/案例匹配几乎没有真实数据。** `news_tags` 1 条、`case_matches` 1 条，且 `rationale` 是 `mock evidence`；当前新闻分析主要靠运行时关键词规则，不是完整的标注匹配。
3. **回答“每次三点”不是硬编码文本，而是 prompt 把结构写死了。** 模型内容会变，但“3–5 个知识点 → 2–3 条迁移 → 边界 → 一个检查问题”的形状每轮都出现，所以看起来像模板。

对比另一个系统：**对方赢在知识覆盖和自然表达；我们赢在案例落地、边界条件、追问和证据。** 当前回答是“好教练”，但不是“完整答完问题的老师”。

## 1. 标签系统评估

### 1.1 数据现状

查询 `.learning-agent/data/learning.db`：

| 表 | 数量 | 说明 |
|---|---:|---|
| `content_blocks` | 744 | 教材段落/表格/图，ch04 有 47 段 |
| `content_tags` | **0** | 教材段落标签完全没有生成 |
| `news_tags` | **1** | 仅 1 条，且是 mock 数据 |
| `case_matches` | **1** | 仅 1 条，`rationale = 'mock evidence'` |
| `knowledge_points`（ch04） | 50+ | 有 6 组同名重复知识点 |

重复示例：

```text
消费者购买行为        kp_consumer_buying_behavior / kp_ch04_g_1bf5919c
消费者购买决策过程    kp_consumer_decision / kp_ch04_g_b04f5ce7
消费者行为的一般过程  kp_consumer_behavior_process / kp_ch04_g_4b673fbe
消费者与消费者市场    kp_consumer_market / kp_ch04_g_30f28401
数智消费者的购买决策过程  kp_digital_consumer_traits_2 / kp_ch04_g_69dc1b67
数智消费者的心理与行为特征 kp_digital_consumer_traits / kp_ch04_g_77f4450f
```

### 1.2 用户说的“按教材自己分的段打 tags”有没有实现？

**没有真正实现。**

- `pipeline/ingest-resources.ts` 把教材拆成 `content_blocks`，但没有写 `content_tags`。
- `packages/db` 有 `upsertContentTags()`，但全仓库没有调用点。
- `pipeline/tag-ch4.ts` 是对**新闻**做知识点匹配，不是对教材段落打标签。
- `content_tags` 表存在，所以“设计上预留了”，但“数据上没有跑”。

这意味着：

- 系统无法按“教材第几段 → 哪个知识点”检索；
- 解释只能依赖知识点定义 + 关键词匹配 + 新闻片段；
- 用户感觉“硬编码/不智能”是有依据的。

### 1.3 为什么 tags 是英文？

当前标签体系用的是内部枚举：

| 字段 | 英文值 | 用户应看到 |
|---|---|---|
| `tag_role` | `core` / `example` / `mention` | 核心 / 例证 / 提及 |
| `tag_type` | `knowledge_point` / `competency` / `decision` | 知识点 / 能力 / 决策 |
| `method` | `rule` / `llm` / `hybrid` | 规则 / 模型 / 混合 |
| `tag_key` | `kp_consumer_definition` | 消费者（名称） |

UI 里确实有英文/内部 ID 泄漏：

- `NewsAnalysisRenderer` 直接显示 `match.role`，所以出现 `core`；
- `NewsView` 直接显示 `match.tag_role` 和 `match.kp_id`，所以出现 `core`、`kp_*`。

这是显示层没有做“内部枚举 → 中文标签”的映射，不是标签本身必须英文。

### 1.4 匹配度为什么感觉不高？

三个原因叠加：

1. **没有教材段落标签。** 匹配只能从知识点名称/关键词/定义出发，缺少“这段教材在讲哪个知识点”的锚点。
2. **新闻/案例标签几乎没有。** `news_tags`/`case_matches` 只有 mock 数据；真实新闻分析走 `NewsLabAgent` 的运行时关键词选择，置信度经常固定 0.7，角色固定 `core`。
3. **知识点有重复。** 同名知识点分裂成两个 ID，匹配时投票被拆散，UI 也可能显示两个相似项。

另外，`Matcher` 的规则兜底是“句子命中关键词 → 0.45 + ratio*0.5”，置信度是启发式，不是校准过的概率；LLM 匹配 prompt 只要求最多 3 条，容易“凑满 3 条”。

### 1.5 标签系统建议（不改代码，仅评估）

1. **补教材段落标签 pipeline**：`content_blocks` → `content_tags`，按 section/paragraph 生成 `knowledge_point` 标签，带 `evidence_span`、`tag_role`、`confidence`、`review_status`。
2. **中文显示映射**：`core→核心`、`example→例证`、`mention→提及`；`rule→规则`、`llm→模型`、`hybrid→混合`；永不显示 `kp_*`。
3. **去重知识点**：按 name + aliases 合并 ch04 的 6 组重复；保留 canonical ID，旧 ID 做 alias。
4. **匹配阈值与“证据不足”**：低于阈值不返回；不要为了凑 topK 把弱匹配标成 core。
5. **匹配解释**：每条匹配显示“教材段落 + 新闻原句 + 为什么匹配”，而不是只显示英文 role。

## 2. 回答质量对比

### 2.1 同一个问题

> 在营销中，谁是消费者，消费者能干什么

### 2.2 另一个系统的回答（图 1）

优点：

- 覆盖“狭义消费者 / 广义消费者”两种定义；
- 覆盖消费决策中的 5 个角色：发起者、影响者、决策者、购买者、使用者；
- 覆盖消费者在营销中的 5 个作用：需求源头、交易核心、传播节点、创新来源、关系资产；
- 有儿童安全座椅的例子；
- 结构完整，像教材/百科式回答。

不足：

- 没有引用课程材料；
- 没有明确边界条件；
- 没有针对学生状态的追问；
- 更像通用知识回答，不是学习教练。

### 2.3 我们的回答（图 2）

优点：

- 紧扣课程定义：“为生活消费而购买和使用产品或服务的个人和家庭”；
- 抓住两个关键词“生活消费 / 个人和家庭”；
- 用“公司采购电脑 vs 自己买电脑打游戏”区分消费者市场与组织市场；
- 有可迁移结论、边界条件、检查问题；
- 有 1 条依据；
- 更像一个教练在带学生判断。

不足：

- **没有回答“消费者能干什么”**：缺少决策角色（发起者/影响者/决策者/购买者/使用者）和消费者作用；
- 没有覆盖“广义消费者/狭义消费者”的区分；
- 结构过于固定：第一、第二、第三 → 可迁移三条 → 边界 → 要不要继续；
- 读起来像模板，而不是根据问题自然组织；
- 对“谁是消费者”回答得很深，但对“能干什么”回答得很少。

### 2.4 评分对比（1–5，主观评估）

| 维度 | 另一个系统 | 营小商 | 说明 |
|---|---:|---:|---|
| 知识正确性 | 5 | 5 | 两者定义都正确 |
| 知识覆盖度 | 5 | 2.5 | 我们漏了角色/作用/广义狭义 |
| 案例落地 | 2.5 | 4.5 | 我们的采购/生活消费例子更贴课程 |
| 边界条件 | 2 | 4.5 | 我们明确组织市场边界 |
| 结构自然度 | 4 | 3 | 我们模板感明显 |
| 互动/追问 | 1 | 4.5 | 我们有检查问题 |
| 证据/引用 | 1 | 4 | 我们有 1 条依据 |
| 个性化/状态 | 1 | 4 | 我们有章节/学习状态 |
| 标签透明度 | N/A | 2 | 英文 role / 内部 ID |

**结论：**

- 如果目标是“回答一个营销知识问题”，另一个系统更好：覆盖全、表达自然。
- 如果目标是“带学生用案例学会判断”，我们更好：有边界、有追问、有证据。
- 但用户当前期待的是“既懂知识、又会教”的老师；我们的回答在“懂知识”这一半明显偏窄，所以显得不智能。

## 3. “为什么每次输出都三点”

### 3.1 不是文本硬编码，是结构硬编码

`packages/agent/src/chat.ts` 的 system prompt 明确要求：

```text
如果是知识解释、新闻分析或案例讲解：
先给结论；
再拆 3–5 个知识点，每个知识点用“概念 + 原文证据 + 为什么成立”；
然后给 2–3 条可迁移结论；
最后说明边界条件。
每个知识点写 2–4 句。
```

同时 `composeReply` 每轮都会带一个 `checkQuestion`，UI 固定显示“想一想”。

所以模型会稳定输出：

```text
第一、第二、第三
可迁移的三条
边界条件
要不要我接着用……
```

内容会变，但**形状不变**。用户感觉“硬编码”是合理的。

### 3.2 这个 prompt 适合什么、不适合什么

适合：

- 复杂案例/新闻分析；
- 需要学生形成判断规则的解释；
- 有明确边界和迁移目标的学习场景。

不适合：

- “谁是消费者”这种定义题；
- “消费者能干什么”这种清单/角色题；
- 简单事实问答；
- 学生只想快速确认一个概念时。

### 3.3 建议的回答策略（不改代码）

先判题型，再决定结构：

| 题型 | 建议结构 |
|---|---|
| 定义题 | 一句话定义 + 1 个正例 + 1 个反例/边界；不强制三点 |
| 角色/作用题 | 直接列角色/作用，按逻辑分组；不要先讲定义再硬拆三点 |
| 对比题 | 表格或双栏对比 + 判断规则 |
| 案例题 | 结论 → 知识点 → 案例证据 → 迁移 → 边界 |
| 计划/产出 | 判断 → 取舍 → 下一步；卡片附件 |

同时：

- `3–5 个知识点` 改为“按内容需要，1–5 个”；
- `2–3 条迁移` 改为“有迁移价值时才给”；
- 检查问题改为可选，简单事实题不要每轮都问；
- 增加“问题覆盖检查”：学生问了两个部分，必须两部分都回答。

## 4. 总体判断

### 4.1 我们的系统 vs 别人的系统

| 维度 | 判断 |
|---|---|
| 知识广度 | 别人更好 |
| 表达自然度 | 别人更好 |
| 案例/课程贴合 | 我们更好 |
| 边界与判断规则 | 我们更好 |
| 互动与追问 | 我们更好 |
| 证据与状态 | 我们更好 |
| 标签/匹配透明度 | 我们更差（英文枚举、几乎无真实标签） |
| 整体“智能感” | 目前别人更像“会答”，我们更像“会教但答不全” |

### 4.2 为什么用户觉得“不智能”

不是模型完全不会，而是：

1. 教材段落 tags 没生成，系统没有真正的“教材证据层”；
2. 新闻/案例匹配几乎是 mock/规则，置信度不真实；
3. UI 暴露英文枚举和内部 ID；
4. prompt 把回答形状写死，简单问题也被迫套“三点 + 三条 + 边界”；
5. 对“消费者能干什么”这种问题，回答覆盖不全。

### 4.3 优先级建议

**P0（影响智能感最大）**

1. 补 `content_blocks → content_tags` 的教材段落标注；
2. 标签中文化，禁止 UI 显示 `core` / `kp_*`；
3. 回答 prompt 改为题型自适应，简单题不强制三点；
4. 增加“问题覆盖检查”，先答完再教练式追问。

**P1**

5. 去重 ch04 同名知识点；
6. 新闻匹配用真实标注 + 阈值，不再固定 0.7/core；
7. 显示匹配依据（教材段落 + 新闻原句 + 理由）。
