# 营小商 · MVP v3

> **口径**：一个智能体 + 提示词 / 工具 / skill；上下文由模型按需取。
> 原则见 [`../principles/single-agent.md`](../principles/single-agent.md)；
> 需求细节见 [`../requirements/`](../requirements/README.md)。本文只回答：这一轮交付什么、怎么验收。

## 0. 一句话

学生只聊天。营小商自己判断该做什么、自己调工具取材料、自己写产物；右栏直接看结果。
学生不选章节、不选角色、不看内部状态。

## 1. 与 v2.0 的差别

| 维度 | v2.0 | v3 |
|---|---|---|
| 组织方式 | 按主题章节写在一份长文档里 | 一个需求一份文档，按编号验收 |
| 分工 | 保留「多专家团」作为未来参考 | 明确只有一个智能体；分工名不得上屏 |
| 上下文 | 已退预取，但没写成硬规则 | 目录只给名称+一句话，正文全部工具读，禁止预塞与假已读 |
| 功能落位 | 原则分散 | 统一到 提示词 / 工具 / skill 三分法，禁止代码分支 |
| 产物 | HTML 为主 + 历史分支保留 | 只留 `page` 与 `question_set` 两类；历史分支列待清理 |
| 旧路径 | 说已删，实际仍在 | 列为 MVP 内必须下线的收敛项（R01、R04、R15） |

## 3. 端到端验收（真跑，不写假模型）

| # | 学生说 | 应该发生 |
|---|---|---|
| 1 | 「我想学消费者行为」 | 追问 1–2 句，给最小计划；没有章节下拉框、没有角色选择 |
| 2 | 「直播间为什么让人冲动消费」 | 先调读工具取正文；回复引用原文；给一个检查问题 |
| 3 | 「消费者是什么意思」 | 不拿目录当定义；必须先 `read_kp` 或 `read_material` |
| 4 | 「给我出 3 道题」 | 题目集壳子；可作答、可交卷、逐题解析；作答写证据 |
| 5 | 「帮我设计国潮联名调研」 | 只问一个缺的关键信息；产出研究设计页面 |
| 6 | 「校园二手书 BP」 | 产出 BP 大纲页面，每节写清目的与所需证据 |
| 7 | 「我学得怎么样」 | 成长卡页面；证据不足要明确写出来 |
| 8 | 「那学习呢」（案例精讲后追问） | 只展开被追问的点，不重讲全篇 |
| 9 | 「根据最新消息出题」 | 用最新新闻，不退化回旧文 |
| 10 | 连续多轮 | 摘要、证据、状态各写一次，不重复写 |
| 11 | 学生贴一条自己的新闻 | 能分析、能出题；抓不到就说清楚 |
| 12 | 未配置 Key | 一句人话说明，不吐英文堆栈 |

三条通用判据：

- **产物直接能看**：右栏不出现 `##`、`**`、裸 JSON。
- **回复是人话**：不出现 phase、intent、工具名、置信度、分工名。
- **引用可回原文**：点依据能看到段落，不是只有标题。

## 4. 不做

- 不做第二个会说话的东西：多 agent、角色切换、专家入口、按意图路由。
- 不预取业务材料，不把预取标成「已读」。
- 不给每类产物配代码模板与渲染器（出题除外）。
- 不做登录、多租户、教师端。
- 不做小程序。
- 不做任意命令执行。
- 不做积分、排行、正确率这类知识对错评价。

## 5. 交付顺序

1. **文档统一**（本目录）：原则、需求、MVP 口径对齐。
2. **下线旧路径**：`subagents.ts`、`team.ts`、`news-lab.ts`、`packages/skills` 旧管线、`packages/bundle` 的四个 preset、`packages/ui` 旧 Web 面；确认不再被引用后再删（R01、R04、R16）。
3. **工具与上下文对齐**：目录只给名称+一句话；读工具记账；截断预算（R03、R05、R06）。
4. **产物收敛**：只留 `page` 与 `question_set`；历史 5 个渲染分支与 `apps/desktop/templates/*.md` 清理（R15）。
5. **界面与打包**：文案、错误提示、安装包（R16、R19、R20）。

每步都以「真跑一轮」收尾，不以编译通过代替行为验收。

## 6. 现状差距（摘要）

| 现状 | 违反 | 归属 |
|---|---|---|
| 旧多角色/旧管线文件仍在仓库，且部分仍被调用 | 一个智能体 | R01、R04 |
| 旧 Web 面与 bundle preset 仍按四个「专家」组织 | 一个智能体 | R01、R16 |
| 历史产物保留 5 个结构化渲染分支与 md 模板 | 产物只留两类 | R15 |
| 文档把分工当产品结构写 | 原则 §1 | 本目录已重写；旧文档归档 |
| 提示词 / skill / 手册三层边界在代码里混用 | 三分法 | R02、R04 |

具体证据（文件路径、函数名、行号）写在各自需求的第 7 节。

## 7. 验收方式

```sh
pnpm run typecheck
pnpm run build
pnpm run db:seed
pnpm run db:seed:student
pnpm run dev:desktop
```

行为验收靠把桌面端真跑起来、用真实 Key 走一轮；`scripts/` 不再放返回固定字符串的假模型测试。
打包用 `pnpm run package:desktop`，产物在 `release/`。
