# 文档地图

> **营小商** —— 市场营销伴学智能体
>
> 只有 `00-mvp/` 定义当前口径：`营小商-MVP-v2.0.md` 是产品口径，`营小商-MVP-需求分层-v0.1.md` 是需求的实现分层，`营小商-现状不足与可借鉴-v0.1.md` 是实现差距与改造参考，`营小商-多专家团模式参考-v0.1.md` 是多角色协作的外部参考，`营小商-代码卫生检查-v0.1.md` 是当前代码库里不上场的那部分清单。

## 5. 过时说法对照

看到旧文档里的这些说法时，按右列理解：

| 旧说法 | 现在 |
|---|---|
| 右栏固定"产物 / 记忆 / 评估"三个 Tab | 多标签文档工作区，`+` 打开产物 / 依据 / 过程 / 文件 |
| 入口 Agent 关键词路由、JudgeAgent 拆解 TurnPlan | 模型看着工具清单自己选，不再由规则排程 |
| 顶部章节下拉框 | 从对话推断 scope，不确定才问 |
| 每类产物配一套结构化 schema + 代码模板渲染 | 默认让模型直接产 HTML；只有出题这类要嵌交互的才走结构化 |
| 每轮写一条 episode | 每轮写 `turns`，状态写 `learning_states`，摘要写 `summary_ledger` |
| 6 维能力 | MVP 先做 4 维（问题建构 / 证据与假设 / 决策与取舍 / 沟通与影响） |
| Postgres + pgvector + Meilisearch | 当前本地 SQLite |
| Web 优先 | 桌面端与网页版共用同一份 React 界面 |
| 多用户 | MVP 单学生本地库（`student_demo`） |

## 6. 维护规则

- 新文档先选目录，再加版本后缀（`-v0.x.md`）。
- 只有 `00-mvp/` 能定义当前口径；长远方案放 `10-long-term/`，不要和 MVP 混写。
- 旧版本不删，移到 `90-archive/`，并在文首写清"已被谁取代"。
- 移动文档后，更新本索引和文内相对链接。
- **过程文档不入库**：进度、计划、交接、核对笔记这类东西放 `.scratch/`，不要放仓库根，也不要进 `docs/`。
