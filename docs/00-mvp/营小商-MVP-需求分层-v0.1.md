# 营小商 · MVP 需求分层

> 配套文件：[`营小商-MVP-v2.0.md`](营小商-MVP-v2.0.md)。
> 本文只做一件事：把需求分成 **通用能力 / 交付物 / 硬约束** 三层，方便实现时一眼看清哪些要写成规则、哪些只是交付时处理、哪些是边界。
>
> **一条判定口径**：把需求里的具体案例换成一个不同案例，它还需要成立吗？
> — 需要 → **通用能力**（写成提示词规则或工具）。
> — 只是"这次想看到这个样子" → **示例**，不进代码。

---

## 一、通用能力（从老师要求里提炼）

老师说的是具体场景，实现要落成规则。**右列是明确不能写死的东西。**

| # | 通用能力 | 老师的要求 | 不能写死成 |
|---|---|---|---|
| A1 | 学生直接提问就能用，不选章节、不选专家 | 学生跟智能体互动、问问题 | 章节下拉框、专家选择器 |
| A2 | 分析必须挂在课程知识点上，不能自由发挥 | 用对应的知识点分析案例；结合营销战略 STPB 知识点分析 | 针对某个品牌/某条新闻的代码分支 |
| A3 | 讲到机制层：这个知识点**怎么解释**这个案例，不是定义 + 案例复述 | 老师给了消费者、学习两个范例 | 固定的"定义→案例→对话"段落模板；固定案例 |
| A4 | 评价对象是能力与成长，不是知识对错 | 比考知识更好地考能力进步；比分数更好地考查学生 | 正确率、积分、等级排行榜 |
| A5 | 评价必须有依据，来自学生真实问答与作答 | 智能体逐渐了解学生，评估成长进步 | 按轮数/字数/活跃度编出来的成长分 |
| A6 | 新闻能匹配到知识点，也能匹配到思政点 | 把新闻和知识点匹配，再把思政内容匹配 | 打一堆标签但不参与后续分析 |
| A7 | 能出题，题来自案例/新闻/知识点 | 提供了试题库；用某一章的知识分析、出题 | 只从固定题库抽题 |
| A8 | 学生可以自带一条新闻进来 | 让学生报一个新闻，用某章知识分析、出题 | 只认系统内置新闻列表 |
| A9 | 有调研能力与商业计划书能力 | 还有调研智能体、商业计划书智能体 | 只留空入口 |

## 二、通用能力（MVP 自己必须补）

这些老师没明说，但没有它们，上面九条会退化成死代码。

| # | 通用能力 | 为什么必须有 |
|---|---|---|
| B1 | **章节是可配置的**：加一章只加数据与提示词，不改编排代码 | 老师先要 ch04，后来要 ch07；按章节写死在代码里，第二次就要重写 |
| B2 | **产物是一份可直接展示的内容**（HTML 页面），不靠固定模板渲染 | 讲得好不好取决于组织与举例，模板只能保证格式一致 |
| B3 | **工具白名单**：读材料、查课程、查新闻、写产物；不执行任意命令 | 模型不能碰 shell，能力只能从白名单里来 |
| B4 | **输出适合截图**：版式稳定、字够大、不出现横向滚动 | 老师要拿截图放进 PPT / Word 交报告 |
| B5 | **界面信息密度低**：一屏只服务当前任务 | 学生原话"信息密度太大"，老师认同 |
| B6 | **每轮可追溯**：对话、产物、依据都留记录 | 既是"积累使用数据"，也是 A5 评价依据的来源 |

## 三、交付物（交付期处理，不进代码）

| # | 交付物 | 依赖 | 交付时怎么做 |
|---|---|---|---|
| D1 | 学生真实使用的对话截图，能放进 PPT / Word | A2、A3、B4 | 用真实问答跑一遍，截中栏 + 右栏；不为此改产品逻辑 |
| D2 | 给协作同学的说明与分工 | A1–A9 的现状 | 交付时按本文 + MVP 文档讲一遍，不额外做功能 |
| D3 | 图形标志 | — | 一张图，不影响能力 |

**原则**：交付物靠"产品已经能用"自然产出，不为交付物单独写代码路径。

---

## 四、硬约束（边界，校验用）

不是功能，是不能越过的线。每条都给出校验方式。

| # | 约束 | 校验方式 |
|---|---|---|
| X1 | 内容范围：先 ch04「消费者市场与购买行为分析」做透，再加 ch07「目标市场营销战略」 | 只看这两章有没有跑通全链路 |
| X2 | 匹配**准确**才允许给学生用 | 抽一批新闻做人工核对，给出准确率；不达标不上线 |
| X3 | 名字：营小商 / 营小商伴学智能体；副标题「市场营销伴学」 | 全局搜文案 |
| X4 | **不出现学校名字** | 全局搜校名关键词，命中即不合格 |
| X5 | 对外不说小程序，说桌面软件 | 文案与说明 |
| X6 | 只做单学生本地库，不做登录与多租户 | 仓库内无鉴权/多用户代码 |
| X7 | 时间：老师周末交报告前可用 | 排期 |

## 五、不作为规范的东西

老师给的三个例子**只用于校准"讲得够不够好"**，不是实现规格：

1. 消费者 + 永辉 / 胖东来 / 步步高；
2. 学习 + 胖东来（跨城打卡、行为持久改变）；
3. 一条商业新闻 + STPB 分析。

换一个品牌、换一条新闻、换一个知识点，产品必须一样成立。**出现针对这些内容的特例，就是实现跑偏了。**

---

## 六、不做

- 不做多学生、登录、教师端。
- 不做任意命令执行。
- 不给每类产物配一套代码模板与固定 schema（出题除外，它要嵌交互）。
- 不把内部状态、路由轨迹、置信度写进聊天正文。
