# 营小商 · MVP v2.0

> **营小商** —— 市场营销伴学智能体。学生只聊天，模型判断该做什么、调工具做完，把结果直接做成能看的东西放在右栏。
>
> 这份文档是 MVP 的**唯一权威**：说清展示什么、一轮怎么走、产物怎么出、工具有哪些、怎么验收、跟现在差多少。
> 取代 v1.0 时期的四份文档（设计文档 / 反馈文档 / 附录与零散记录 / 需求整理），旧文整体归档在 `docs/90-archive/00-mvp-v1/`，只用于追溯，不作为实现依据。

---

## 0. 一句话

**提示词 + 工具 + 输出，三件事。**

- **提示词**是系统的活儿：判断学生此刻在干什么、该给他什么，由我们写好、组合好。
- **工具**是能力：读材料、查课程内容、查新闻、写产物。模型自己看着选，不由代码替它排程。
- **输出**尽可能让模型直接做出来。除了必须嵌进我们交互壳子的（目前只有出题），其余一律让 AI 自己组织成页面。

多智能体是加在上面的一层分工，不是另一套架构。**现在没上**——先让单 agent 跑通，多角色的参考见 `营小商-多专家团模式参考-v0.1.md`。

## 1. 边界

| 是 | 不是 |
|---|---|
| 聊天优先的伴学智能体，学生只负责说话 | 功能入口集合，学生先选章节/选专家 |
| 本地优先，单学生 SQLite（`student_demo`） | 多学生账号系统、教师端 |
| 桌面软件（Electron）+ 网页版（`apps/web`） | 微信小程序（不做，别这么对外说） |
| 用真实商业案例练“知识点 → 案例 → 判断 → 证据” | 题库刷题器、论文生成器 |
| 产物是下一轮判断的输入 | 产物是终点 |

MVP 验收章节：第 4 章「消费者市场与购买行为分析」。第 3 章与「市场营销战略」作为第二批内容，不改变验收口径。

## 2. 展示什么

### 2.1 三栏

- **左栏**：新对话、会话列表、学习档案、设置。
- **中栏**：唯一的对话主线。诊断、讲解、追问、出题都在这里发生。
- **右栏**：当前任务的工作区。产物在这里打开，可以多标签、可关闭、可全屏。

### 2.2 右栏能展示的东西

| 类型 | 展示方式 |
|---|---|
| **AI 页面（HTML）** | 跑在沙箱 iframe 里直接渲染；学生要附件时的主路径 |
| 题目集 | 我们的做题壳子：选项、交卷、逐题解析 |
| Markdown / 图片 / PDF / DOCX | 预览，用于教材、新闻原文、旧产物 |
| 任务概览 | 状态、本轮产物、记录水位、新闻库 |
| 依据 | 本轮引用的知识点与原文段落，显示中文名不显示 `kp_*` |

### 2.3 学生不用做的事

- 不用先选章节。章节从对话和状态推断，不确定才问一句。
- 不用选“用哪个专家”。那是模型的事。
- 不用看内部枚举、置信度、工具调用日志、步骤 read/write。
- 不用手动保存、导出才能看。产物生成即可看。

## 3. 一轮怎么走

```text
学生说一句话
   ↓
系统拼提示词：角色 + 当前环境（章节、学情、知识点目录、已有产物）
   ↓
模型看着工具清单，自己决定先干什么（可以连续调多次）
   ↓   读材料 / 查章节 / 查新闻 / 写页面 / 出题
工具返回结果，模型继续
   ↓
模型给一段自然语言回复（人话，不暴露内部结构）
   ↓
产物落到右栏，本轮记录落库，下一轮可引用
```

三条硬约束：

1. **模型不执行指令。** 没有 shell、没有任意命令、没有“跑个脚本”。工具是白名单里的能力，不是终端。
2. **一个说话人。** 无论内部几个人在干活，学生只看到一个人在说话。
3. **不编造。** 没有证据就说证据不足；引用必须能回到原文段落。

## 4. 输出怎么出（本节是核心）

### 4.1 默认：在聊天里讲清楚

学生问「为什么」「这是什么意思」，**就在聊天里讲完**：结论先行 → 拆解 → 迁移 → 边界 → 一个检查问题。

为什么：学生的动作是「扫一眼就知道我卡在哪」，不是「打开一份文档读三页」。右栏是附件区，不是阅读器——每轮都生成一份附件，右栏会被琐碎的东西塞满，学生真正要带走的那些反而找不到。

### 4.2 学生要附件时：模型直接产 HTML

学生**明确要一份能带走的东西**时（「给我一份」「做成附件」「整理成一份」「精讲」「研究设计」「成长卡」），让模型直接写成一份 HTML 页面，右栏渲染。

为什么这类东西不用模板：好坏的差别在“怎么组织、怎么举例、怎么排版才讲得清”，那是模型最擅长、代码最不擅长的事。代码模板只能保证格式一致，保证不了讲得清楚。模板越多，产物越像填空，越不像一个会讲课的人做的东西。

### 4.3 例外：需要学生动手的，走结构化 + 我们的壳子

只有一种情况例外：**产物必须嵌进我们的交互，学生要在里面操作，操作结果还要被系统接着算。**

目前只有出题：

- 答题状态要记（选了哪个、改没改）；
- 交卷要批改、要逐题解析；
- 作答要写成学习证据、进题库去重。

这些是“数据”，不是“页面”，所以必须结构化（`question_set` JSON），由我们的组件渲染成题目卡。

### 4.4 判断标准（两问）

> 1. **学生是不是明确要一份能带走的东西？** 不是 → 聊天里讲完，不产附件。
> 2. 是 → **他要不要在里面动手、动完手系统要不要接着算？** 要 → 结构化 + 我们的壳子；不要 → 直接 HTML。

按这条，研究设计、BP 大纲、成长卡、案例精讲、新闻分析**在“要附件”时全部属于 HTML**，不该再各配一套模板和渲染器。

### 4.5 写进提示词的 HTML 约束

模型的产物不是“能打开的网页”，是“嵌在右栏里的一段内容”。提示词里要写死：

- **单文件、内联样式**，不引外部 CSS/JS/字体/图片链接（离线可用）。
- **不写 `<script>`**。页面是给人读的，不是给人点的；要交互就走 4.3 的壳子。
- **不写全屏布局**：右栏宽度有限，最小按 320px 宽排版，不许横向滚动。
- **不重复标题**：文档头已经有标题，正文从内容开始，别再来一个 `<h1>`。
- **浅底深字**，正文对比度够；不要整页深色底。
- **信息密度服从“讲清楚”**，不是“排满”：能用一个例子讲明白就别堆三段定义。

### 4.6 现在长什么样

这条已经通了：

1. **产物类型有 `page`**：`content_json` 存 `{ title, html }`，落库直接写 `.html` 文件，不再转 Markdown/Word；
2. **右栏是沙箱 iframe**：`ui.tsx` 的 `HtmlFrame` 用 `sandbox=""`（禁脚本、禁同源、禁表单）+ CSP `default-src 'none'`（禁外链，只放开内联样式），模型写的 HTML 进不了主界面；
3. **写入工具只剩两个**：`write_page`（HTML）、`emit_question_set`（结构化），都只在学生明确要的时候才用。

`renderers.tsx` 里那 5 个结构化渲染分支**暂时留着**：旧管线（`packages/skills`）不再接线，但历史产物还在库里，删了就只剩 Markdown 降级。

## 5. 工具

### 5.1 三类

| 类别 | 作用 | 现在有 |
|---|---|---|
| **读数** | 从课程与外部资料里取材料 | `list_chapter_kps`、`read_kp`、`read_material`、`read_textbook`、`read_reference`、`search_news`、`read_news` |
| **写件** | 产出给学生看的东西 | `write_page`（HTML）、`emit_question_set`（结构化） |
| **常规文件** | 读写本地文件，受路径边界约束 | 教材原文、导出的 md/docx/html |

### 5.2 工具的形态要求

- **自描述**：名字、说明、参数 schema 都在工具身上，模型看得懂就会用。
- **可增删**：加一个能力 = 加一个工具 + 改一句提示词。不该牵动调度代码。
- **不耦合内部表结构**：工具对外是“给我 ch04 消费者动机的材料”，不是“给我 kp_id 列表”。内部怎么查是工具的事。
- **有界**：每次返回有长度上限，超了要截断并说明还有多少，不把整本书塞进上下文。

### 5.3 现状

工具已经是注册制，在 `packages/agent/src/tools/`：

- 一条 `ToolSpec` = 一个能力：`name` / `kind`（读或写）/ `description` / `parameters` / `execute(args, turn)`；
- `AGENT_TOOLS` 是全部能力的清单，`agentTools(turn)` 把声明绑到本轮状态，工具自己不持有状态；
- **加一个能力 = 往清单里加一条**，再在提示词里说一句它什么时候用。不牵动主循环，也不改别人的参数列表。

工具对外说人话：`emit_question_set` 收的是知识点**中文名**，`kpIds` 由工具自己翻成内部 id。

### 5.4 材料只给目录，正文由模型读

system 里只放「本章知识点目录」：知识点名 + 小节 + 一句话定义（截 60 字）。
目录明确标注“只用于选材料，不是原文”，不能当引用。

正文由模型调工具取：

- `read_kp`：一个知识点的完整定义、别名、例子、非例子；
- `read_material`：1–4 个知识点的定义 + 教材原文；
- `read_textbook`：更宽的教材原文；
- `search_news` → `read_news`：新闻候选与正文。

为什么不再预取：预取会让代码替模型选材料，把无关知识点塞进上下文；还会把这些内容标成“本轮已读”，模型之后想用工具重读会被拒绝。目录只告诉模型“有什么”，正文让模型自己选，和 §3「模型看着工具清单自己决定」保持一致。

设计与验收见 [`20-features/知识点目录与按需读取-v0.1.md`](../20-features/知识点目录与按需读取-v0.1.md)。

## 6. 谁在干活

现在只有一个 agent。**不是一个角色，是一条主循环**：它自己判断、自己读材料、自己查手册、自己写产物、自己说话。

不上多角色协作的原因很直接：DSH 的多代理在 `packages/experimental/agent-team` 里，是实验特性，MVP 不押它。

专业内容没有因此丢失，只是换了存放方式：

- **一份主提示词** `packages/agent/agents/mentor.md`：身份、判断顺序、回复规矩、边界、该读哪份手册。
- **七份手册** `packages/agent/references/`：案例怎么精讲、题怎么出、调研与 BP 怎么写、能力怎么评、反例怎么找、产物长什么样、该追问还是该讲。模型用 `load_reference` 按需读，不在每轮上下文里常驻。

学生只面对一个说话人，看不出它读过哪份手册、调过什么工具。

多角色协作的完整机制、以及将来真要做时的顺序，见 `营小商-多专家团模式参考-v0.1.md`。

## 7. 验收

### 7.1 场景

| # | 学生说 | 应该发生 |
|---|---|---|
| 1 | 「我想学消费者行为」 | 追问 1–2 句，给出最小计划；没有章节下拉框 |
| 2 | 「直播间为什么让人冲动消费」 | 推断 ch04；一段解释 + 引用原文 + 一个检查问题 |
| 3 | 「给我出 3 道题」 | 题目集壳子；答案折叠；作答写证据 |
| 4 | 「帮我设计国潮联名调研」 | 只问一个缺的关键信息；产出研究设计页面 |
| 5 | 「校园二手书 BP」 | 产出 BP 大纲页面，每节写清目的与所需证据 |
| 6 | 「我学得怎么样」 | 成长卡页面；证据不足要明确写出来 |
| 7 | 「那学习呢」（案例精讲后追问） | 只展开被追问的那个点，不重讲全篇 |
| 8 | 「根据最新消息出题」 | 用最新新闻，不退化回旧文 |
| 9 | 连续多轮 | 摘要、证据、状态各写一次，不重复写 |
| 10 | 未配置 Key | 一句人话说明，不吐英文堆栈 |

### 7.2 三条通用判据

- **产物直接能看**：右栏不出现 `##`、`**`、裸 JSON。
- **回复是人话**：不出现 phase、intent、工具名、置信度。
- **引用可回原文**：点依据能看到段落，不是只有标题。

## 8. 现状与差距

不粉饰。以下是设计口径和现在代码的实际距离。

| 设计口径 | 现在的代码 | 差距 |
|---|---|---|
| 讲解留聊天，要附件才产 HTML | 讲解走聊天；`write_page` / `emit_question_set` 只在学生明确要附件时用 | 符合（历史产物仍走旧渲染分支） |
| 加能力 = 加工具 + 改提示词 | `tools/` 下一条 `ToolSpec` 一个能力，`AGENT_TOOLS` 是清单 | 符合 |
| 调度由模型看工具自己定 | 单循环，9 个工具全在模型手上，代码不再按正则判断意图 | 符合 |
| 学生只看到一个人在说 | 单 agent，天然只有一个说话人 | 符合 |
| 不执行指令 | agent 侧无 `child_process`，工具全是白名单能力 | 符合 |
| 材料只给目录，正文由模型读 | system 只放知识点目录；`prefetchMaterial` 已删，正文走 `read_kp` / `read_material` / `read_textbook` / `read_news` | 符合 |
| 一套实现 | 旧路径、成员机制、6 个 `emit_*` 已删除 | 符合 |

代码规模：`packages/agent/src` 共 6167 行；其中主提示词 186 行、手册 837 行、主循环 227 行、工具 792 行、循环体 313 行、产物落库 132 行。

**收敛顺序**（不改变本文口径，只是把代码拉回来）：

1. ~~删旧路径~~：已完成（`handleTurn`、`judgePlan`、`subagents.ts`、`registry.ts`、`router.ts`、`chat.ts`、`inquiry.ts`）。
2. ~~收敛为单 agent~~：已完成（`MEMBERS`、`memberTool()`、`MEMBER_ARTIFACTS`、`memberEmitTools()` 已删；6 份角色提示词合并为 1 份主提示词 + 7 份手册）。
3. ~~加 HTML 通道~~：已完成（`page` 类型、`.html` 落库、`HtmlFrame` 沙箱、导出走 `html` 格式）。
4. ~~产物收敛~~：已完成（6 个 `emit_*` → `write_page` + `emit_question_set`）。历史产物的 5 个渲染分支暂时保留，理由见 §4.5。
5. ~~工具注册制~~：已完成（`tools/types.ts` 定义 `ToolSpec`，`tools/read-tools.ts` 与 `tools/write-tools.ts` 是清单，`tools/index.ts` 负责绑定）。
6. 清掉不上场的代码：死包、死文件、装配了却不调用的服务，清单与顺序见 `营小商-代码卫生检查-v0.1.md`。

## 9. 不做

- 不做多学生、登录、教师端（长远设计见 `10-long-term/`）。
- 不做小程序。
- 不做任意命令执行。
- 不给每个产物配一套代码模板——那是 §4 明确要退掉的方向。
- 不把内部状态、路由轨迹、置信度放进聊天正文。
