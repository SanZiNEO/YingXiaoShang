# 营小商 · 校信息化办公室需求清单

> 用途：向学校信息化办公室说明「哪些事我们自己做不了、需要学校支持」。
> 提交时可自行补机构全称与联系人；本文件不含任何密钥、账号或学生真实数据。
> 版本：v1 · 2026-11-07

---

## 〇、一页纸摘要

**我们做了什么**：一个市场营销课程的 AI 学习助手（桌面软件，学生解压双击即用）。
已经能在**完全不依赖学校服务器**的情况下跑通完整教学闭环：提问 → 查教材原文 → 出题 → 作答 → 交卷判分 → 学情档案。

**现在缺什么**：只有两件事真正需要学校：

| 需求 | 为什么自己办不了 |
|---|---|
| ① 手机端 / 小程序 | 需要学校主体资质（个人主体无教育类目）、域名备案、教育 APP 备案 |
| ② 班级共用的新闻与资料库 | 需要一台长期在线的服务器 + 域名 + 数据合规口径 |

**我们希望的沟通方式**：不是「要一套资源」，而是请学校在三种方案里挑一个**对学校最省事**的（见第一节）。
方案 A 几乎不需要信息办出手；方案 C 才需要全套资质。

**我们承诺**：不对外宣传、不涉及学校名义、不做商业化、学生数据只用于教学。

## 一、三种方案（请学校选一个，我们照着做）

| | 方案 A：纯本地 | 方案 B：校内服务器 | 方案 C：公网 + 小程序 |
|---|---|---|---|
| **形态** | 学生电脑上的桌面软件，各用各的 | 校内一台服务器，学生校内网访问网页版 | 公网服务 + 手机网页 + 微信小程序 |
| **能做到** | 问答、出题、判分、学情档案（已完成） | A 全部 + 全班共用新闻库 + 手机看进度 | B 全部 + 学生随时随地用 |
| **需要学校** | 几乎不需要（仅 API 额度口径 + 终端白名单） | 服务器 + 内网域名 + 统一认证对接 + 数据存放许可 | 全套：公网 IP/域名备案/SSL/教育 APP 备案/等保 |
| **备案** | 不需要 | 仅内网一般不涉及 ICP 备案 | **必须**：ICP 备案 + 公安备案 + 教育 APP 备案 |
| **等保** | 不需要 | 按学校规定（通常内网系统不强制测评） | 一般要求二级等保测评 |
| **费用** | 模型 API 费（一学期几十到几百元） | 服务器约 1000–3000 元/年 + 运维 | 服务器 + 等保测评（3–8 万/次）+ 运维 |
| **上线周期** | 现在就能发 | 2–4 周（走校内资源申请） | **2–4 个月**（备案 2–4 周 + 等保整改） |

**我们的建议**：先走 **方案 A** 让两个班用起来，用真实反馈决定要不要升到 B/C。
**如果学校只支持一件事，请支持方案 A 的两件小事**（见第六节），其余我们自己扛。

## 二、需要资质/主体的事（个人身份无论如何办不了）

### 1. 微信小程序主体资质 ★最关键

- **要什么**：以学校（或学校授权单位）为主体注册小程序；教育类目需要《事业单位法人证书》，部分类目还要《办学许可证》。
- **为什么我们办不了**：微信开放平台对**个人主体**不开放教育类目；个人主体也拿不到办学资质。学生/教师个人身份无法上架教育类小程序。
- **能不能绕开**：能。**不做小程序**，改做手机浏览器网页版（不需要小程序主体，但需要方案 C 的公网域名与备案）。代价是没有微信入口，学生要收藏网址。
- **周期**：主体注册 1 周内；类目审核看材料。

### 2. ICP 备案（域名备案）

- **要什么**：一个可对外提供服务的域名，备案主体为学校或学校授权单位。
- **为什么我们办不了**：`edu.cn` 域名由学校统一管理，通常不对个人项目开放子域；个人备案不能用于教育类对外服务。
- **能不能绕开**：能。**仅校内访问**时可用内网地址（如 `10.x.x.x` 或校内域名），不需要 ICP 备案。
- **周期**：2–4 周（管局审核），期间不能对外提供服务。

### 3. 教育移动互联网应用程序备案（教育 APP 备案）

- **要什么**：面向学生提供教育类应用（含小程序、APP、网页），需在教育部「教育移动互联网应用程序备案管理平台」备案，**备案主体是学校**。
- **为什么我们办不了**：备案主体必须是学校；个人无法提交。
- **能不能绕开**：**不完全能**。如果只在校内、只对本课程学生使用，是否纳入备案由学校判断——这是我们需要学校明确答复的第一个问题。
- **周期**：通常 2–4 周，需学校盖章材料。

### 4. 公安联网备案

- **要什么**：网站/应用上线 30 日内在全国互联网安全管理服务平台备案。
- **为什么我们办不了**：主体是学校；一般学校已有统一账号。
- **能不能绕开**：走方案 A/B 不涉及。

### 5. 软件著作权 / 开源合规（非必须，但影响后续）

- **要什么**：如果未来要以学校名义发布或申请项目，可能需要软著登记；我们使用了若干开源组件，需确认许可证（均为 MIT/Apache 类，可商用）。
- **需要学校**：确认知识产权归属口径（学生作品 / 职务作品 / 学校与个人共有）。

## 三、需要长期花钱的事

> 以下为参考区间，**以学校实际采购价为准**；我方不申请经费，只请学校判断可否承担或指导我们走哪条路。

| 项目 | 参考费用 | 什么时候需要 | 能不能省 |
|---|---|---|---|
| 云服务器（2 核 4G，含 40G 系统盘） | 1000–3000 元/年 | 方案 B/C | 用学校现有虚拟化资源可省 |
| 带宽 / 流量 | 1000–2000 元/年（5Mbps）或按流量 | 方案 B/C | 校内网访问可省 |
| 对象存储（存新闻正文、导出文件） | 几十–几百元/年 | 方案 C | 存服务器本地盘可省 |
| 域名 | 30–100 元/年 | 方案 C | 用学校现有子域可省 |
| SSL 证书 | 0（免费证书）–1000+ 元/年 | 方案 C | 免费证书够用 |
| 大模型 API 调用 | **一学期几十到几百元**（按 token 计费，视使用量） | A/B/C 都需要 | 见下条 |
| 短信验证码（如做手机号登录） | 约 0.03–0.05 元/条 | 方案 C（可选） | 用学号+口令可省 |
| **等保二级测评** | **3–8 万元/次**（含整改） | 仅方案 C 公网对外 | **只做 A/B 就不需要** |
| 运维人力 | 学校现有 | 长期 | 我们可承担日常，但需要有人兜底 |

### 关于大模型 API 费用（最需要学校定口径的一件事）

- 现在用的是**开发者个人申请的测试额度**，不适合一个班长期使用：额度用尽时全班同时报错，费用也烧在个人账上。
- 三个可选口径，请学校选：
  1. 学校已有统一大模型服务/网关 → 我们对接（最理想）
  2. 学校出一张专用 API 账号，费用走教学经费
  3. 明确「仅限教学演示、不进正式教学环节」，我们继续用个人额度但**限制人数与时长**

> **说明**：学生提问内容会发送给模型服务商（国内厂商，数据不出境），这属于个人信息处理行为，需要学校知情并给出口径（见第四节第 3 条）。

## 四、需要学校网络与账号体系支持的事

### 1. 校园网出口放行 ★容易踩坑

- **要什么**：确认学生电脑/校内服务器能访问模型服务的 API 域名（HTTPS 443）。
- **为什么需要**：部分校园网对第三方 API 有出口限制或需要代理；一旦被拦，学生看到的就是「连不上模型服务器」。
- **能不能绕开**：不能。**这是方案 A 也会遇到的问题**，请帮忙确认放行或告知正确的代理配置。

### 2. 统一身份认证对接（方案 B/C）

- **要什么**：CAS / OAuth2 接口文档与测试账号；用学号登录，避免我们自己管账号密码。
- **为什么需要**：自建账号体系意味着我们要存学生密码，安全责任与合规风险都不该由课程项目承担。
- **能不能绕开**：能。方案 A 不需要登录（本机单用户）。

### 3. 校内服务器 / 虚拟化资源（方案 B）

- **要什么**：1 台 Linux 虚拟机（2 核 4G，40G 盘），或告知申请流程与配额。
- **为什么需要**：全班共用的新闻库、手机网页版必须有一台 7×24 在线的机器。
- **能不能绕开**：能。不做手机端与共享库就不需要（方案 A）。

### 4. 子域名与内网 DNS（方案 B/C）

- **要什么**：一个校内可解析的域名（如 `xxx.edu.cn` 子域）或内网地址。
- **能不能绕开**：能。用 IP + 端口（体验略差，且证书问题麻烦）。

### 5. 软件分发渠道

- **要什么**：一个稳定的下载位置（学校对象存储 / 内网文件服务），或确认可以放在班级群文件。
- **为什么需要**：现在靠网盘/群文件分发，学生常遇到下载不全、被杀毒软件拦截。
- **能不能绕开**：能（继续用群文件），但会持续有「装不上」的支持成本。

### 6. 终端安全软件白名单 ★容易踩坑

- **要什么**：如果学校统一部署了终端管控/杀毒软件，请把本软件加入信任（说明：绿色免安装、仅读写自己的数据目录）。
- **为什么需要**：Electron 应用与自解压启动器**经常被误杀**，学生看到的症状是「双击没反应」。
- **能不能绕开**：不能完全绕开。可以提供签名版，但代码签名证书本身也要花钱。

## 五、数据合规与安全（需要口径，不一定需要投入）

| # | 事项 | 需要学校做什么 | 我们的现状 |
|---|---|---|---|
| 1 | 学生个人信息范围 | 明确哪些字段可以采集（建议只要学号/姓名/班级，不要手机号、身份证） | 只存学号与姓名、学习行为 |
| 2 | 数据存放位置 | 明确「可以存公有云 / 必须存校内」 | 现在只存在学生本机，不上传 |
| 3 | 个人信息处理告知与同意 | 提供或审核一份《告知同意书》模板；明确是否需要签署 | 我们可起草，需学校审核 |
| 4 | 数据保留与删除 | 明确保留期限（如课程结束后 6 个月删除） | 可一键导出/删除 |
| 5 | 日志留存 | 网络安全法要求网络日志留存不少于 6 个月（方案 C 适用） | 方案 C 时补 |
| 6 | 安全责任人与应急联系人 | 指定一位老师/管理员作为对接人 | 需要 |
| 7 | 等保测评 | 方案 C 才需要；请学校明确是否强制 | 方案 A/B 不涉及 |
| 8 | 数据出境 | 目前模型服务为国内厂商，**数据不出境** | 若改用境外模型会触发，届时另行报备 |

## 六、如果学校只能支持两件小事（方案 A 路径，强烈建议先做这个）

1. **确认校园网能访问模型 API 域名**（或给出正确代理配置）。
2. **终端安全软件加白名单**（避免学生「双击没反应」）。

这两件不需要花钱、不需要备案、不需要走采购，但直接决定第一批学生能不能用起来。

## 八、明确不需要学校出面的部分（我们的边界）

以下都由我方自己完成，**不占用学校资源**：

- 软件开发、测试、打包、发布包制作
- 交付包（158MB，42 个文件，解压双击即用，含启动自检与失败自救）
- 14 组自动化测试（每次改动都跑，防止改坏）
- 学生端错误提示中文化（断网/密钥/余额/磁盘/启动失败都有具体指引）
- 日常答疑与使用文档
- 数据备份与恢复方案（学生本机数据可一键导出）

## 九、时间线与关键路径

```
方案 A（现在）
  ├─ 校园网出口确认 ──┐
  ├─ 杀毒白名单     ──┤→ 2 个班试用 → 收集反馈 → 决定是否升级
  └─ API 口径确认   ──┘        （2–4 周）

方案 B（若要手机看进度 + 共享新闻库）
  ├─ 校内服务器申请（1–2 周）
  ├─ 统一认证对接（1 周）
  └─ 上线（合计 2–4 周）

方案 C（若要公网 + 小程序）
  ├─ 主体资质与类目（1–2 周）
  ├─ ICP 备案（2–4 周，期间不可对外服务）
  ├─ 教育 APP 备案（2–4 周，可并行）
  ├─ 等保测评与整改（1–2 个月，可与开发并行）
  └─ 上线（合计 2–4 个月）
```

**关键路径**：方案 C 的瓶颈不是开发，是**备案 + 等保**。所以我们建议先 A 后看。

## 十、风险与备选

| 风险 | 影响 | 备选 |
|---|---|---|
| 小程序主体批不下来 | 无微信入口 | 改手机网页版（方案 C 但不做小程序） |
| 等保测评无法安排 | 不能公网对外 | 只做校内（方案 B），学生用校园网访问 |
| API 额度无口径 | 无法长期给一个班用 | 限制为演示用途；或改用学校统一网关 |
| 校园网出口受限 | 学生用不了 | 提供离线模式（本地教材与题库已内置，仅新闻与问答需联网） |
| 终端安全软件拦截 | 安装失败 | 提供签名版 + 白名单流程 |
