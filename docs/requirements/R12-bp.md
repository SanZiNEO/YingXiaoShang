> 状态：MVP（本轮）
> 依赖：[R04](R04-skills.md)、[R05](R05-context-on-demand.md)、[R15](R15-artifacts.md)
> 代码：`packages/bp/src/index.ts`、`packages/agent/references/research-bp-playbook.md`、`packages/agent/agents/mentor.md`
> 上位原则：`../principles/single-agent.md`

## 1. 要什么（学生可见结果）

学生说「校园二手书 BP 怎么写」「帮我列个商业计划书目录」时，得到一页**大纲**，不是一份计划书正文：

- 一句话定位：这份 BP 给谁看、要促成什么。
- 每节写四件事：**这一节要回答什么问题、需要什么证据、现在有没有、最容易被质疑的地方**。
- 目录按「问题 → 机会 → 方案 → 验证 → 执行 → 财务 → 风险」组织，不照抄模板八股。
- 每个数字要么标来源，要么明确标「假设」；没有来源的数字不得写成事实。
- 结尾列「决定成败但当前缺失的证据」，再给一个先补哪一节的动作。

学生要附件时产出 HTML 页面（`page`）；不要附件就在聊天里给目录骨架。**不替学生写完整计划书。**

## 3. 行为（一轮里怎么发生）

1. **还原场景**：问清（或从上下文推断）给谁看、课程要求、团队阶段；只补一个真缺的信息。
2. **给定位**：一句话写清这份 BP 的目的，学生不认就改这一句。
3. **给目录**：七段骨架，按项目实际删减，不硬凑八股。
4. **逐节标证据**：每节四字段；已有 / 待补 / 教学假设三态必须选一个。
5. **标关键缺口**：把「决定成败但现在没有」的证据单列。
6. **给下一步**：先补哪一节、为什么。
7. **要不要附件**：学生要「一份」才 `write_page`；否则聊天里给目录。

## 4. 契约

### 4.1 页面骨架（`write_page` 的 `html`）

| 小节（`<h2>`） | 必须写清 |
|---|---|
| 一句话定位 | 给谁看、要促成什么（融资 / 课程作业 / 校内评审） |
| 大纲 | 每节一行：标题 + 目的 + 所需证据 + 状态 + 最大风险 |
| 数字与口径 | 哪些数字有来源、哪些是假设、哪些待补；财务只给计算口径 |
| 关键缺口 | 决定成败但当前缺失的证据 |
| 下一步 | 先补哪一节，为什么 |

### 4.2 每节的四个字段

| 字段 | 含义 | 反例 |
|---|---|---|
| 目的 | 这一节要回答的问题 | 「介绍市场」 |
| 所需证据 | 需要的数据或材料类型 | 「市场数据」 |
| 状态 | 已有 / 待补 / 教学假设，三选一 | 留空或写「部分」 |
| 最大风险 | 这一节最容易被质疑的地方 | 「注意风险」 |

### 4.3 数字规则

- 有来源：写来源类型与时间（「据 XX 2024 年报告」），并说明口径。
- 无来源：写「假设」并给假设依据；**不得**以陈述句写成事实。
- 财务：给公式与关键假设（客单价 × 频次 × 转化），不给拍脑袋的三年营收数字。
- 页面里不出现内部 id、置信度、阶段标签。

## 5. 边界（不做什么、失败怎么表现）

- **不代写成品**：不产出完整 BP 正文、章节正文、财务模型文件。
- **不虚构数据**：不编市场规模、增长率、竞品份额；缺数据时写「待补」并说明该从哪类来源取。
- **不堆框架**：不把 STP、4P、SWOT、商业模式画布全铺一遍；用哪个说明为什么。
- **不越界评价**：BP 写得好不好属 [R13](R13-growth-card.md)，这里只标证据缺口。
- **失败表现**：学生只给一个词（「二手书」）→ 先问给谁看/什么阶段中的一个，再给骨架；学生要「直接写完」→ 给大纲 + 一节示范段落，说明其余留给他。

## 6. 验收（场景 → 期望）

1. **「校园二手书 BP」** → 右栏出现大纲页面，每节都有目的、所需证据、状态、最大风险；没有一节只写标题。
2. **数字审查**：页面里任何市场规模/增长率要么带来源，要么标「假设」；出现无来源陈述句数字即判不合格。
3. **「帮我把这份 BP 写完」** → 只给大纲与一节示范，明确说正文由学生写；不产出整篇正文。
4. **「给我个融资用的 BP 目录」** → 定位写清「给投资人看、要促成约谈」，财务节给口径不给数字。
5. **只要口头建议** → 聊天里给七段目录，右栏不新增产物。

## 8. MVP 范围与后续

**MVP 做到哪**

- BP 只出大纲页面：定位 + 七段目录 + 每节四字段 + 关键缺口 + 一个下一步。
- 数字三态（有来源 / 假设 / 待补）必须显式标注；财务只给口径。
- 不产出 BP 正文、不产出财务模型、不导出 docx。

**后续**

- 补一份 `bp-coach` skill（判据）：每节四字段齐全、数字三态齐全、不代写正文（[R04](R04-skills.md)）。
- 旧 `BpService` 退场：确认无人调用后删除服务、`defineTool` 工具集、`bp_projects` / `bp_sections` 写入与 `bp_outline` 渲染分支。

**明确不做**

- 不做章节正文生成、不做财务预测模型、不做 `export_bp` 式旁路导出。
- 不做 BP 自动评分与分级评审。
