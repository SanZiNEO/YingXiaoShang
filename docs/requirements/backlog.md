# 未立项需求（backlog）

> 这里的东西**不在 MVP 里**，也不该出现在 `docs/requirements/R01–R20` 的实现口径中。
> 每条写清：要什么 / 为什么现在不做 / 什么条件下才立项。
> 立项时新建 `Rnn-*.md`，从本文件移除，并更新 `README.md` 的需求表。

## B01 多租户、登录与教师端

- **要什么**：学生账号、班级、教师查看与批改、权限。
- **为什么现在不做**：MVP 是单学生本地 SQLite；账号体系会把「本地优先、聊天优先」的假设全部推翻。
- **触发条件**：出现第二个真实班级，且教师端有明确的批改动作（不是只看数据）。
- **来源**：旧长远设计文档（系统拆解、能力评价）。

## B02 六维能力评价、申诉与教师校准

- **要什么**：在 4 维之外补齐洞察/策略/品牌/数据/沟通/伦理六维；rubric 分级；学生申诉；教师校准与一致性检验。
- **为什么现在不做**：MVP 只做 4 维 + 形成性反馈 + 成长卡；没有足够标注数据，六维打分会退化成编分数。
- **触发条件**：至少一个学期、两个班级的真实对话证据，且教师愿意做双人标注。
- **来源**：旧能力评价需求拆解。

## B03 案例卡库与检索层

- **要什么**：结构化案例卡（事实、利益相关者、决策问题、约束、数据、冲突、rubric）；Postgres + pgvector + Meilisearch；案例与知识点的多对多。
- **为什么现在不做**：当前出题与精讲直接基于知识点 + 新闻原文，已能跑通；先验证教学效果再建库。
- **触发条件**：新闻匹配准确率稳定达标，且出现「同一案例反复讲、需要复用与版本管理」的需求。
- **来源**：旧案例库方案。

## B04 向量检索与自动 rerank

- **要什么**：语义召回 + 重排，替代「本章目录全量给模型自己选」。
- **为什么现在不做**：单章知识点规模（约 40 条）目录足够；向量检索会引入新的服务与调参成本，且违反「目录只给名称」的简单性。
- **触发条件**：单章知识点超过 200 条，或跨章检索成为常态。
- **来源**：旧知识体系规范。

## B05 LMS / SSO 集成

- **要什么**：与学校 LMS 对接、单点登录、成绩回写。
- **为什么现在不做**：没有确定的对接方与协议；先做本地可用的桌面软件。
- **触发条件**：课程方给出正式接口文档与试点班级。
- **来源**：旧系统拆解。

## B06 云部署与多端

- **要什么**：容器化、多用户并发、Web 端重新上线、移动端。
- **为什么现在不做**：MVP 明确只做 Windows 桌面端；Web 面已下线，避免第二套界面与第二套口径。
- **触发条件**：B01 立项且并发与数据隔离方案确定。
- **来源**：旧系统拆解。

## B07 多智能体协作

- **要什么**：多个角色/子代理分工、消息总线、任务板。
- **为什么现在不做**：**永久排除**，见原则 §1。内部分工只能落在提示词、工具、skill 三处；任何需要「第二个会说话的东西」的方案都不立项。
- **触发条件**：无。若将来确有需要，先改原则，再谈实现。

## B08 微信小程序

- **要什么**：小程序端。
- **为什么现在不做**：**明确不做**，对外也不这么说。当前交付形态是桌面软件。
- **触发条件**：无。

## B09 学生自带语料与文件上传

- **要什么**：学生上传自己的案例材料（PDF/DOCX/图片），营小商读它并分析。
- **为什么现在不做**：MVP 只支持贴一条新闻链接/文本；上传会引入解析、版权与存储边界。
- **触发条件**：出现真实课堂作业要求「用自己的材料」。
- **来源**：需求分层 A8（自带新闻）的扩展。
