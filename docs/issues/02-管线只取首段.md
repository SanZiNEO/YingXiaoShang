---
title: "[pipeline] pickDefinition 用 find() 只取首段，知识点小点被丢弃"
labels: pipeline, bug, knowledge
priority: P0
---

## 根因

`pipeline/lib/knowledge.ts` → `pickDefinition()`：

```ts
function pickDefinition(paragraphs: string[]): string {
  const substantial = paragraphs.find(
    (paragraph) => paragraph.length >= 20 &&
      (/[。！？]$/.test(paragraph) || /是指|指的是|是为|定义为/.test(paragraph)),
  )
  if (substantial) return substantial      // ← 只返回第一段，同节其余段落全部丢弃
  const medium = paragraphs.find((p) => p.length >= 12)
  if (medium) return medium
  if (paragraphs.length > 0) return paragraphs.slice(0, 4).join('；')
  return ''
}
```

`extractBodySections()` 其实把整节段落都收进了 `section.paragraphs`，是这里 `.find()` 把它们丢掉了。

## 复现

以第 7 章「品牌战略的类型」为例，docx 正文有 `（1）品牌化战略 /（2）品牌名称战略 /（3）品牌延伸战略 /（4）品牌再定位战略` 四段，
入库后 `definition` 只剩第一段 29 字。ch01/ch06/ch08/ch10 的占位符条目同理（ingest-report 里已有 warning，但**这只覆盖"完全没有正文"的情况，截断不报警**）。

## 两种修法

**A. 直接拼接（改 3 行）**

```ts
const substantial = paragraphs.filter(/* 同样的判定 */)
if (substantial.length) return substantial.join('')
```

代价：定义会变成 200–400 字，和规范「定义 1–3 句」冲突，卡片展示也会失控。

**B. 按数据模型拆（推荐）**

- `definition` 保持现在的短句逻辑；
- 被丢弃的后续小点，用规范里已有的 `parent_id` 拆成**子知识点**
  （例：`kp_ch07_929b6ddd` → 「无差异营销 / 差异化营销 / 集中化营销」）；
- 或加 `details` 字段存完整正文，`definition` 只做摘要。

B 的好处：短定义仍然适合卡片展示，机制层内容也能被检索、被出题、被评价。
