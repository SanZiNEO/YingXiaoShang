## 2. 阅读顺序

### 2.1 新人 30 分钟路线（可执行三步）

1. **先读用例全貌**：打开 `11-scenario-catalog.md` §1 结论摘要与 §2.2 用例总表，弄清 31 条 TC 如何分 P0 冒烟主干 / P1 回归面，各自主维度、启动路径、外部依赖与确定性等级。
2. **再查反查地图**：打开 `01-execution-map.md` §4.1 反查总表，挑一条 P0 用例（建议 `TC-P0-01`），顺着「关键 IPC 方法名 + `文件:行` → 关键表/文件 → 证据来源」三列，分别到 `03` 契约表、`08` 数据表、`10` launch 草案定位它落地在什么位置。
3. **最后落第一个冒烟用例**：按 `10-harness-strategy.md` §4.3.1 最小基线实验跑通 `_electron.launch` → `firstWindow()` → `learning.health()` → 截图 → close；基线通过后再按 `11` §2.4 串行编排 P0 主干，实测结果回填对应 TC 卡片。

### 2.2 写用例时怎么查

- 按 IPC 方法查覆盖状态与归属 TC：`01` §4.2；方法契约字段/入参/返回形状：`03` §4.3（invoke）与 §4.2（通道）。
- 确定性分级（高/中/低，决定断言能写到多细）：`07` §2.2；fixture 造数、隔离 home 与清理回收：`08` §4.5/§5/§6；等待信号/截图/日志/回收约定：`10` §4.4。
- 页面与流程归属：`01` §4.3 与 `04` §2.1/2.2；新用例编号与卡片字段格式：`11` §4 与 `../AUTHORING-SPEC.md` 第 4 节。

### 2.3 排查故障时怎么查

- **已知 TC 编号**：先在 `01` §4.1 定位它打到哪个 IPC 方法（`文件:行`）、哪张表/文件、哪个外部面；再翻对应主文档的「风险与坑」节。
- **选择器/定位问题**：`04` §4 定位现状与 R-2/R-5；**sidecar/端口/网络**：`06` §5 R-1/R-8；**DB 脏读/三件套/隔离**：`08` §7 风险 1/4；**打包路径与 asar 内外**：`05` §5 风险 1/4；**错误对象跨 IPC 形态**：`03` §4.2 R-1；**既有脚本能否复用**：`09` §4 覆盖矩阵。

## 3. 维护规则

1. **ID 只追加不改号**：新事实 ID 一律在所属主文档末尾追加新编号；已有 ID 的编号、含义、归属不得改写，废弃号不得复用。
2. **同一 ID 只在主文档定义**：BOOT/WIN 归 `02`；CH/IPC/EVT 归 `03`；UI/FLOW 归 `04`；PKG 归 `05`；EXT 归 `06`；SVC 归 `07`；DATA 归 `08`；LEG/G 归 `09`；TC 归 `11`。其他文档只引用、不定义。
3. **新增用例编号规则**：P0 续 `TC-P0-14`…、P1 续 `TC-P1-19`…；引入新前缀（新领域/新通道）须先经主代理批准，再在对应主文档开段；`01` 与本索引页不得自行编号。
4. **行号漂移以函数名兜底**：源码改动后行号会移动；定位先以函数名 / `case '<method>'` 标签为准，行号作辅助锚点；发现漂移先回填主文档，再同步 `01`。
5. **证据等级要求**：每条事实标 `[源码]` / `[实测]` / `[日志]` / `[待验证]`；索引层转引沿用主文档等级；未运行的用例断言不得写成已验证结论。
6. **联动约束（改了某篇必须同步 `01`）**：任一主文档新增/删除/移动 ID、调整契约或行号后，必须同步更新 `01` §4.1 反查总表与 §4.2/4.3 分维度索引；新增 TC 后在 `01` §4.1 补行，并按 §6 重新核对缺口归类。
7. **各篇负责人（按文件归属）**：每篇主文档对自己定义的 ID 台账、契约准确性与风险节负责；`01` 对索引与反查一致性负责；本 README 对文档地图与阅读路径负责。
