# 04 · 文档模板与引用规范

> 四份文档各管一段，**不合并、不改名、不换顺序**。下面的二级标题是可执行的验收清单：缺一节就算没写完。
> 每节末尾的「必须包含」是硬要求，评审时逐条对。

## 通用头（四份文档都要有）

```markdown
# <轮次> · <文档角色>

> 轮次：A · 服务端骨架
> 文档角色：01-scope / 02-contract / 03-implementation / 04-acceptance
> 冻结口径：[`../00-master/01-frozen-contracts.md`](../00-master/01-frozen-contracts.md) v1
> 写权：[`../00-master/02-ownership-and-parallel.md`](../00-master/02-ownership-and-parallel.md) §1
> 一句话：<这份文档让人能直接开工的那句话>
```

## `01-scope.md`（范围与边界）

| 节 | 必须包含 | 参考要求 |
|---|---|---|
| `## 1 目标` | 3–6 条可判定的目标，每条写明「谁受益、怎么看出来」 | ≥1 个 `[Rn]` |
| `## 2 非目标` | 明确不做的条目 + 为什么不做（防止范围蔓延） | ≥1 |
| `## 3 真实依据` | 现状代码证据表：`路径:行号`、这段代码现在干什么、为什么必须改 | ≥1 |
| `## 4 与现行为的差异` | 有意收紧/放宽的每一条，写「现状 → 契约 → 影响谁」 | ≥1 |
| `## 5 产物清单` | 文件级清单（路径 + 作用 + 是否新建），与写权矩阵逐条对齐 | ≥1 |
| `## 6 并行边界` | 只读依赖、运行期资源（端口/目录/容器名）、互斥锁 | ≥1 |
| `## 7 未知与风险` | 每条含「怎么验证这个风险是否发生」 | ≥1 |

## `02-contract.md`（契约）

| 节 | 必须包含 | 参考要求 |
|---|---|---|
| `## 1 契约总览` | 与冻结文件对应关系：哪些是冻结的、哪些是本轮细化的 | ≥1 |
| `## 2 接口契约` | 逐接口/逐方法：入参表（字段/类型/必填/默认/边界）、返回表、JSON 示例、状态码 | 每个方法至少 1 个 `[Rn]` 或指向同节参考 |
| `## 3 数据结构` | 表/对象字段：名称、类型、可空、来源（哪个表/哪个函数）、示例值 | ≥1 |
| `## 4 错误与消息` | 错误码 → HTTP → 中文消息（逐字），触发条件，客户端应做什么 | ≥1 |
| `## 5 事件与序列` | SSE/流式/多步流程的时序图（文字版）+ 每个事件的字段 | ≥1 |
| `## 6 兼容与版本` | 旧客户端怎么活、字段增删规则、弃用策略 | ≥1 |
| `## 7 契约测试映射` | 每个契约点对应哪条测试（E 轮编号或本轮自测编号） | ≥1 |

## `03-implementation.md`（实现方案）

| 节 | 必须包含 | 参考要求 |
|---|---|---|
| `## 1 目录与模块` | 目录树 + 每个文件职责（一句话），与产物清单一致 | ≥1 |
| `## 2 依赖与构建` | 运行时/构建依赖、包管理器、`pnpm install --ignore-workspace` 与否、镜像阶段 | ≥1 |
| `## 3 关键实现` | 按功能分小节；每节给「输入 → 步骤 → 输出」和伪代码/关键代码片段 | ≥1 |
| `## 4 数据读写` | 读哪些表/写哪些表、事务边界、索引、并发（WAL/busy_timeout） | ≥1 |
| `## 5 配置` | 环境变量表（名/默认/作用/谁设），与冻结表一致 | ≥1 |
| `## 6 失败处理` | 每条失败路径 → 错误码 → 用户看到的中文 → 是否重试 | ≥1 |
| `## 7 性能与资源` | 预期 QPS/延迟/内存/镜像体积，以及怎么量 | ≥1 |
| `## 8 实施顺序` | 可中断的 5–10 步，每步「做完能验证什么」 | ≥1 |

## `04-acceptance.md`（验收）

| 节 | 必须包含 | 参考要求 |
|---|---|---|
| `## 1 验收口径` | 一句话定义「过」，并列出**不可替代**的硬指标（数量/数值） | ≥1 |
| `## 2 前置条件` | 环境、数据、账号、端口、命令；缺什么就明说「缺则跳过并标记」 | ≥1 |
| `## 3 用例清单` | 表格：`AC-01` 编号 / 操作步骤 / 期望输出 / 失败判据 / 证据文件 | 每 3 条至少 1 个 `[Rn]` |
| `## 4 证据` | 证据落点路径、命令输出片段、时间戳、如何复跑 | ≥1 |
| `## 5 反向验证` | mutation / 故意改坏 / 越权 / 空数据；必须写「改坏哪一行 → 哪条用例变红」 | ≥1 |
| `## 6 排查表` | 症状 → 最可能原因 → 一条命令确认 | ≥1 |
| `## 7 自检输出` | `python plans/server-client-split/00-master/check-docs.py` 的原文输出 | ≥1 |

## 写作硬规则

1. **长度**：每份 ≥120 行；`02-contract.md` 与 `03-implementation.md` ≥150 行。宁写表格不写空话。
2. **具体**：不写「做好错误处理」，写「`limit` 非整数 → 400 + `limit 必须是整数。`」。
3. **可执行**：命令必须是能直接粘进 PowerShell 的，含工作目录。
4. **不重复**：冻结文件里已有的整张表不要抄；引用「见 `01-frozen-contracts.md` §5 第 7 行」。
5. **不虚构**：不确定的参数写「未知，验证方法：…」，不写假数字。
6. **中文**：正文中文；标识符、命令、字段名保持英文原样。
7. **代码引用**：`路径:行号` 必须真实。写之前用 `Select-String` 确认行号，别凭印象。
8. **外部参考**：只用 [`03-references.md`](03-references.md) 里的编号，或你自己现场搜到的真实 URL；每个 `##` 节至少 1 个。
9. **不写 TODO**：`TODO`、`待补`、`略`、`后面再说`、`……` 一律视为未完成（脚本会报）。
10. **每份文档自成闭环**：读者只拿这一份 + 冻结文件，就能干活；不要写「详见另一份的第 3 节」而不给要点。
