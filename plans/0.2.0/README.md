# 0.2.0 计划索引（状态看板）

> 本目录是「按 DSH 原生运行时重建」的计划与派单索引。
> 唯一依据：[`docs/agent-runtime-audit-and-rebuild-guide.md`](../../docs/agent-runtime-audit-and-rebuild-guide.md)。
> 需求口径仍是 R01–R20；本目录只管**怎么落地**，不改「要什么」。

**状态图例**：✅ 已完成　🔵 方向已确认、未开工　🟡 讨论中/待定　☐ 未开工　⊘ 不做

## 通用原则（全文沿用）

- **一个文档一个点**，不写伪代码，写实现思路与每一步的交付物。
- **先底层后应用**：先把运行时装对、跑通，再往上挂教学能力。顺序反了会把运行时缺陷误判成提示词问题。
- **不维护自己的过时东西**：切换完成后删掉旧循环，不留 fallback、不写兼容 shim。取消的决定只在 `implementation-progress.md` 留一行 `⊘ 不做`。
- **不设固定轮次/请求数/总时长**（审计 §4.4.3）。请求数是诊断数据，不是达标配额。
- **先全量堆上去，再砍**：把 DSH 的能力先整套接上、跑起来，再剪掉不要的。DSh 是 MIT，直接拿来用；自己重写一个「相似但不完整」的东西是上一轮最大的浪费。
- **主代理不写业务代码**：只建图、拆单、验收。派单与验收走 [`主代理-轮次任务模板.md`](主代理-轮次任务模板.md)。
- **正文只写现行口径**：不写「原本打算 X，后来改 Y」。这类沿革进 `implementation-progress.md`。
- **一轮一个派单文件**：`ROUND-X-MAP.md` 是那一轮的唯一索引，行号只用于定位，以符号名为准。

## 工作方式（主代理 → 子代理）

**具体派单协议、验收约定、红线、汇报格式全部在 [`主代理-轮次任务模板.md`](主代理-轮次任务模板.md)。** 每开一轮，把「模板 + `ROUND-X-MAP.md`」一起交给主代理，它就能执行已定好的计划。

这里只留主干：

1. **定方向**：本文件 + 审计文档。
2. **拆小方向**：一轮一个 `ROUND-X-MAP.md`，里面是「编号 + 目标一句话 + 验收」。不写实现细节。
3. **建图**：先核清本轮涉及的真实文件与符号，结论回填 MAP，不每轮全量重扫。
4. **派调查**：不确定的事实先派调查子代理（读代码、读上游、跑一次），不靠猜。
5. **派执行**：调查完、验收写清，再派执行子代理，**一次只做一轮的一部分**。
6. **验收**：主代理独立复跑，不采信子代理自述；不通过就补齐信息重派。
7. **冲突**：文档多了必然打架。发现冲突**不许自行取舍**，`ask` 人拍板，结论回填 `pending-discussions.md`。
8. **回填**：每关掉一项就在 `implementation-progress.md` 划线，不攒到最后。

**红线**：子代理不许改「要什么」，只许改「怎么做」；不许为了通过验收改验收。
