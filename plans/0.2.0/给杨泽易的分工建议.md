## 一、分工原则（为什么这么切）

**切割线是目录，不是话题：**

| 你可以直接改 | 我改，你需要时提 issue |
|---|---|
| `apps/server/**`（新建） | `packages/**`（业务内核，15 个断言脚本咬合） |
| `services/**` | `apps/desktop/**`（打包与 IPC 契约） |
| `tools/**` | `packages/agent/agents|references`（提示词） |

**为什么 `packages/*` 不给你**：不是信任问题——那里有 15 个断言脚本守着行为，
改动会连带影响「判题、学情档案、历史压缩、取消」这些互相咬合的地方。
你要动其中任何一处，写清「为什么必须动 + 预期影响」发我，我来改，这样回归成本最低。

**为什么服务端骨架给你**：你比我熟这块，而且它跟采集服务、Docker、压测是同一套技能栈。
接口契约我会给你（见任务 A 的输入），产品逻辑我这边适配。

## 二、第一批（本周）

### A. 服务端骨架 `apps/server`

**目标**：把现有业务装进一个 HTTP 服务，供浏览器与将来小程序使用。桌面端继续存在（演示 + 离线兜底），但它不再是唯一形态。

**输入（我提供）**：
1. **IPC 方法清单**：`apps/desktop/src/preload/index.ts` 里 `window.learning.*` 的全部方法 + `apps/desktop/src/main/index.ts` 的 `ipcMain.handle(...)` 分支。这就是要映射成 REST/RPC 的接口全集。
2. **装配参考**：`apps/desktop/src/main/index.ts:60-130`（cordis `Context` + `ctx.plugin(...)` 装配顺序）。服务端应复用同一套 `packages/*` 插件，不要重写业务。
3. **数据表**：`packages/db/src/index.ts`（schema + DAL，先原样复用 SQLite，PG 迁移在任务 D）。
4. **鉴权语义**：现有 `assertSessionOwner` / `assertQuestionSetOwner` 的归属校验逻辑要保留——**不要自己发明一套权限模型**。

**要求**：
- 框架你选（Fastify / Express / Hono 都行），在 PR 里写一句为什么。
- 会话：先做「学号 + 口令」兜底（密码用 scrypt/argon2 存哈希），接口预留 CAS/OAuth2（学校统一认证）。
- 每个请求显式带 `studentId`，服务端校验资源归属；**不要信任客户端传的 studentId 而不校验**。
- 输出 **OpenAPI 3**（`docs/contracts/openapi.yaml`）：这是任务 E 的输入，也是我写 Web 前端的依据。
- 单条 `docker compose up` 能起（与任务 C 合并）。
- 日志：请求 id + 学生 id + 耗时 + 错误分类；**6 个月留存**是学校审计要求，先留好字段。

**验收**：
1. 用 mock LLM 走完「登录 → 提问 → 出题 → 交卷 → 查档案」五步，curl 或脚本能复现。
2. OpenAPI 覆盖所有方法（数量与 `ipcMain.handle` 一致，脚本可核对）。
3. `docker compose up` 后 `/health` ok，重启不丢数据。
4. 40 并发粗略压一遍不崩（正式压测在任务 F）。

**已知坑（省你时间）**：
- `ctx.provide('llm', ...)` 的顺序不能乱，桌面端是按 `llm → learningDb → matcher → ...` 装配的。
- 用户消息必须带 `role:'user'` + `source:{kind:'user'}`，缺了会报一个误导性的 `transport failed`。
- 不要同时订阅根 `ctx` 与 `agent.ctx` 的事件，会重复。

### B. 新闻正文质量抽检

**为什么**：50 个源里必然有一批抓回来是导航栏、登录墙、Cookie 提示、或「正文 == 摘要」。
这些进了库，模型就会拿它们当材料讲。**源的数量不值钱，能用才值钱。**

**交付**：`services/news-crawler-py/scripts/quality_report.py`
按源统计：正文长度分位（P10/P50/P90）、正文≈摘要比例、导航词命中率（登录/注册/Cookie/扫码/版权所有）、
`content_hash` 重复率、空标题/空日期比例；每源给 3 条最差样本（截断 200 字）。

结论给出三类：**保留 / 降级为只取标题摘要 / 下线**。

**验收**：在真实库上跑出报告（`plans/0.2.0/news-source-quality.md`），明确指出最差 5 个源 + 证据。

---

### C. 采集服务 Docker 化

**为什么**：`electron-builder.yml` 只打包 `out/**`、`templates/**`、种子库、提示词，
**永远不会带 `services/` 与 `.venv`**。所以采集服务的正式形态就是服务器上的容器。

**交付**：`Dockerfile`（`python:3.12-slim`，只装 `httpx/beautifulsoup4/lxml`，不含 Playwright）、
`docker-compose.yml`（服务 + 数据卷 + 健康检查 + 应用服务）、cron 示例（30 分钟一轮）。

**验收**：`/health` ok、`/run` 能入库、`restart` 后数据还在、镜像 < 400MB。

**约束**：采集只写 news 相关表（`news_articles`、`source_runs`、`news_tags`），**不要碰学情/题目/会话表**——
服务端与采集会共用同一个 DB 文件，两边都 WAL + busy_timeout=5000，但写锁竞争是要避免的。

## 三、第二批（下周）

### D. SQLite → PostgreSQL 迁移 + 双跑校验

**为什么**：一个人用 SQLite 没问题；40 人同时写会打架。M1 上线前必须换。

**交付**：`tools/migrate-pg/`
- schema 类型映射（TEXT/INTEGER/REAL/JSON → text/bigint/double/jsonb）
- 批量导入（COPY）
- **幂等**：重复跑不重复插入
- **双跑校验**：逐表比对行数 + 抽样内容 hash，不一致非零退出
- 回滚说明

**验收**：`seed/learning.db` 上跑通、行数一致；手改 PG 一行后校验能报错；跑两遍不报错。

---

### E. 契约测试

**为什么**：我改 Web 前端、你改服务端，没有契约就会各写一套。

**交付**：`tools/contract-tests/`
- 从 `docs/contracts/openapi.yaml` 生成用例（或手写 + 用 schema 校验响应）
- 每个方法：合法输入 → 断言结构；非法输入 → 断言**中文可执行**的错误消息
- 能对「本地 Electron 实现」和「HTTP 服务」两边跑（同一套断言）

**验收**：覆盖全部方法；至少 3 条能变红（故意改错一个返回字段 → 对应用例失败）。

---

### F. 压测 + 可观测性

**交付**：
- `tools/loadtest/`：40–60 并发（登录 → 提问 → 出题 → 交卷），模型可切 mock/真实；输出 P50/P95/P99、错误率、`SQLITE_BUSY` 次数
- `/metrics`：请求数、按学生 token 消耗、P95、错误分类；80% 用量告警

**验收**：能回答这个问题——**「某学生今天用了多少 token、问了几轮」**。学校按学生核算额度要用它。

## 五、流程：分支 + PR + 一次复核

你现在是直接推 main。三个实际问题：

1. 我这边 `git fetch` 经常不通（网络），本地和远程一分叉就只能手工同步
2. 没有第二双眼睛——我们上一轮独立复核抓出 1 个 P0 + 7 个 P1，其中一条是**我自己写的正则违反设计原则**，自查看不出来
3. P0（桌面包里没有 Python 服务）也是在推完 main 之后才发现的

所以：`feat/xxx` → PR → 我做一次复核（给到行号的意见）→ 改到过 → 合并。

**PR 描述三件套**：改了什么（一句话）、怎么验证的（命令 + 结果）、**哪里还不确定**（这条最重要）。

## 六、技术约定

1. 采集只写 news 相关表。
2. 正文 <300 字只作线索，不入库；入库条目必须带 `content_status`（full/partial）。
3. 单源失败记 `partial`，不要整轮 fail。
4. 不引入需要编译的依赖；Playwright 只作可选 extra。
5. 密钥不进仓库（`.env.local`、`.venv`、`.artifacts` 已 gitignore）。
6. **不要用 LLM 给新闻打标**：走「人工打标 + 分类器」，先做 **13 章级**，不要一步到位 228 个知识点。
   分类器要**可解释**（命中词/相似度），老师会问「为什么这篇算第 7 章」。
