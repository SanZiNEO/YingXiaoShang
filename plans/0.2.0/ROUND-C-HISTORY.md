# C 轮（切片二）：历史瘦身

> 状态：**已实现、已自测、复核中**。提交 `a16810a`。

---

## 一、要解决的问题

同一会话「越聊越慢」。本机实测曲线：

| 会话 | 逐轮耗时 |
|---|---|
| `chat_mw5xw4fo_d9rrhy` | 2.8 → 2.8 → **61.3** → **76.4** |
| `chat_mvfao3ns_w1g7v6` | 3.0 → **43.0** → **204.8** |

机制：每轮把 `listChatMessages(sessionId)` 的**全部历史原样重发**。
历史线性增长 → 输入 tokens 线性增长 → prefill 变慢，而且上下文越多，
模型越倾向多读几份材料（轮数也涨），两个因素相乘。

## 二、做法

`packages/agent/src/history.ts`（纯函数，无 IO）：

| 规则 | 值 | 为什么 |
|---|---|---|
| 逐字保留最近轮数 | 3 轮 | 「刚才那个」「上面那个例子」靠这几轮维持指代 |
| 单条助手消息上限 | 1200 字 | 回答可能上千字，整段重发纯浪费 |
| 逐字部分上限 | 7000 字 | 第二道闸；默认单条上限下不会咬合，调大单条上限时才起作用 |
| 摘要上限 | 700 字 | 摘要自己不能变成新的膨胀源 |
| 摘要来源 | `memory_episodes` 会话摘要 → 不够再用学生问句首句 | 复用 C 轮切片一修好的摘要，避免再调一次模型 |

摘要放进 **system** 的 `## 之前聊过什么（程序压缩，不是学生原话）`，
不从消息角色上假装是学生说的话。

## 三、验证

### 断言脚本（能变红）

`scripts/verify-history-budget.ts`，17 条断言覆盖：200 轮不膨胀、最近 3 轮逐字、
长回答截断、空/短历史不产摘要、摘要优先级、可复现。

变红实验（证明不是假测试）：

| 破坏方式 | 结果 |
|---|---|
| `HISTORY_DIGEST_MAX_CHARS = 0` | 3 条失败（摘要缺失相关） |
| `HISTORY_KEEP_TURNS = 999` | 2 条失败（没折掉老消息） |

> 唯一没有为它单独变色的是 `HISTORY_MAX_CHARS`：默认单条截断 1200 × 3 轮
> 已经低于 7000，这条闸在默认配置下不会咬合。脚本里用「显式 maxChars=7000 +
> 关掉单条截断」的用例（2b）覆盖这条路径，并额外断言总量 ≤ 9000 这个真正的不变量。

### 端到端（真实调用链）

`probe/a0-dsh/b10-history-budget.mts`，同一会话连问 8 轮：

```
第 6 轮   7.0s | 若全量重放 4443 字 | 实际历史 5865 字 | 调用 2 次
第 7 轮   1.6s | 若全量重放 5409 字 | 实际历史 2763 字 | 调用 1 次
第 8 轮   4.6s | 若全量重放 5572 字 | 实际历史 1944 字 | 调用 1 次

峰值历史 5865 字 ✅ 有界
```

「若全量重放」是线性增长的对照列；实际历史在第 7 轮开始被压回去。

## 四、已知取舍

1. **早期细节会丢**。摘要只保留「问过什么 + 阶段 + 产出」，不保留当时的原话。
   学生说「把第一轮那个定义再讲一遍」时，模型需要重新读材料——这比拖慢每一轮划算。
2. **产物不靠历史传递**。附件由界面右栏打开、由数据库保存；历史压缩不会删产物，
   但如果学生用「上面我们写的那份 20 题」指代，模型可能不知道是哪一份，
   需要重新调用写工具或问一句。
3. **摘要有时序**。`memory_episodes` 由 recorder 后台写，刚聊完的那一轮可能还没摘要，
   这时摘要里少了最近的内容——但最近 3 轮本来就在逐字部分里，所以不影响。
