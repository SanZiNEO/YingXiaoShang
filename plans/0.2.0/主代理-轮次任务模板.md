# 主代理 · 轮次任务模板（0.2.0 版）

> 改编自 `omp-主代理-轮次任务模板.md`。原模板是 Minecraft 模组项目（gradle + 实机截图），
> 本文件只换「验证手段」与「项目根」，**方法论原样保留**。
> 每开一轮，把本文件 + `ROUND-X-MAP.md` 一起给主代理，就能执行已定好的计划。

## 一、本轮目标

- 轮次：`{{轮次}}`（A / B / C / D / E / F）
- 项目根：`G:/市场营销ai/learning-agent`
- 依据：`docs/agent-runtime-audit-and-rebuild-guide.md` + 本轮 `ROUND-{{轮次}}-MAP.md`
- 范围：只做本轮 MAP 列出的范围，不改其他轮次的代码与文档
- 标准：**拒绝最小实现**，以可验收的完整实现为准，时间成本不计
- 收口标准（优先于「最小改动」）：本轮内做完、做干净——单一入口、单一判定；**不留双写入口、不留并行判定、不留「以后再说」的兼容层**。0.2.0 在 F 轮收口，**没有专门的清理轮替本轮擦屁股**
- 过渡策略：默认「本轮内完整最优」，新实现直接取代旧写法。只有 MAP 显式要求保留旧行为时才兼容，且必须写清**谁在哪个轮次关掉它**
- 冲突处理：MAP 自相矛盾 → 先 `ask` 裁决，不自行二选一；裁决结果写进 MAP，后续轮次沿用

## 二、阶段 0：建立项目地图

1. **先做任务书自检**：目标 / 范围 / 验收 / 不做 四项是否齐全且互不矛盾。有互斥约束先 `ask`，不带着矛盾开工。
2. 读本轮 MAP + 它列出的文档（**不通读整个 docs/**，只读本轮范围；需要交叉引用再 `grep` 定位）。
3. 用 `read` / `grep` / `find` 建立地图：模块 → 目录 → 关键符号 → 调用入口；核对**已完成轮次**的边界，避免重复实现。
4. 结果落到 `plans/0.2.0/ROUND-{{轮次}}-MAP.md`，含：
   - 任务清单（编号 + 一句话目标 + 验收标准）
   - 真实文件路径、符号名、调用入口
   - 任务之间的依赖顺序
   - 已确认的现状与缺口（缺口分「本轮做 / 移交后续轮次 / 契约边界」三类）
5. 后续派单**引用这份地图**，不每轮全量重扫项目。

> `docs/90-archive/` 只作线索，不得作为实现依据；冲突时以 `principles/` + 源码为准。
> 审计文档是**调查结论**，其中标 `[INFERENCE]` 的条目需要本轮复核后才能当事实用。

地图完成后，先输出 10 行以内的计划摘要，再进入派单。

## 三、阶段 1：计划与 todo

- 用 `todo` 把地图里的任务逐条落成待办，一项一行，可独立验收。
- 每完成一项**立刻**更新，不攒着批量更新。
- 按依赖排序；无依赖的并行派发。

## 四、阶段 2：派单协议

每个子任务必须**自包含**，五项缺一不可：

1. **目标**：一句话，可判定是否完成
2. **材料**：准确的文件路径、符号名、相关文档章节、现有实现位置
3. **交付物**：改/建哪些文件，什么格式，**不要动哪些文件**
4. **验收**：具体命令与期望结果
5. **回报**：改动文件清单 + 验证方式 + 未解决项（分类：本轮补齐 / 移交后续轮次并写明轮次与关闭条件 / 契约边界）

派单硬性要求：

- 任务描述末尾固定加一句：**「思考过程用中文」**
- 要求子代理**先复述任务再动手**；复述不符就重新派
- **第一行动作写死**：`delegate_task` 的子代理空转（整轮只在回答里推演、一个文件没写）是最常见失败——第一行必须写「**第一动作 = 直接 `write` / `edit` 指定文件**，不要在回答里推演代码」，并给足签名与常量，压缩它的设计空间
- **禁止全量构建**：用模块级命令 `pnpm --filter @learning-agent/<pkg> build`，不要 `pnpm -r build`
- **并发子代理不要各自跑构建**：同一工作区会抢锁。派单时写死「不要跑 build、不要 commit」，由主代理在**每个波次结束后统一跑一次**编译；失败按「补齐信息重派」处理
- 明确写「不要做什么」，堵住偷懒与扩大改动面
- 子代理没有对话、不能反问；信息不足就补齐再派，不让它猜

## 五、阶段 3：验收

子代理返回后逐条执行：

1. 看 `git diff`，改动范围是否与交付物一致
2. 跑该项验收命令；**主代理独立复跑**，不采信子代理自述
3. 对照验收标准逐条确认；不通过就**补齐信息重派**，不在原上下文里打补丁

**探针约定（本项目版）**：

- 探针放仓库外：`G:/市场营销ai/probe/<轮次>-<任务号>/`，**不入库**；临时日志、夹具同样处理，测完还原
- 探针用 `tsx` 直跑 TS 源，不依赖打包产物：`pnpm exec tsx G:/市场营销ai/probe/<dir>/probe.ts`
- 假模型/假 ctx 起步（参考 `scripts/verify-max-rounds.ts` 的 `fakeCtx`），能在无网络、无数据库下判定
- 探针自己打印 `PASS` / `FAIL` 行 + 汇总，失败退出码非 0——主代理只看这两处就能判定
- 涉及真模型的验证单独列出，标注「需 Key / 需网络 / 会产生费用」，不混进常规验收

## 六、阶段 4：进度节奏

每完成 **3** 个子任务或一个派单波次（先到者），报一次：

```
进度：{已完成}/{总数}（{百分比}）
已完成：…
进行中：…
阻塞：…（缺什么信息 / 等什么结果）
下一步：…
```

## 七、收尾交付

- 变更清单（按文件）
- 每项验证结果（命令 + 结果摘要）
- 遗留与移交：每条写明「本轮必须做 / 移交后续轮次（轮次 + 关闭条件）/ 契约边界」
- **deprecated 不许悬空**：本轮新增的每个兼容入口/字段/路径，必须本轮写清「归属轮次 + 关闭条件」；没有承接轮次的，**本轮直接删**，不留到下一轮
- 未做的事，明确说没做

**轮次移交（硬性）**：任何「设计了但本轮没做」或「实现时发现更好方案」，不能只写在总结里——必须写进 `plans/0.2.0/implementation-progress.md` 或 `pending-discussions.md`，带归属轮次与关闭条件。属于「设计已定但本轮不做」的，在对应文档标「未实现（归属轮次）」；发现更好方案的，写清原方案 / 新方案 / 为什么更好 / 谁落地，**不得静默改口径**。

## 八、红线

- **该问的**：MAP 自相矛盾；缺外部约束或业务偏好（默认行为是否允许变化、平台边界、兼容期长度）；不可逆或影响面大的取舍
- **不该问的**：实现方案的最优解已由原则/设计文档确定时——典型如「删旧格式 vs 保留双入口」「合并两套判定 vs 并存」——直接选「干净、单一入口、无兼容层」，标 deprecated + 写迁移说明，**不问**。把这类问题抛给用户等于把该自己做的判断外包
- 其余设计口径有疑问 → **先用 `ask` 问，不自行假设**
- 不编造 API、字段、路径：不确定先 `grep`；指不到来源的结论标「未验证」
- 不越界改本轮范围外的代码；但 MAP **显式列出**的跨轮文档清理属本轮范围
- 不做完就报「已验证」；没跑过的验证不许说通过

## 九、本项目经验（持续追加）

1. **别改默认值就以为改了我**：`tool-loop` 默认值曾被 `team.ts` 里写死的参数覆盖，改默认值一点效果都没有。**先 `grep` 全部调用点，再决定改哪。**
2. **写检查器先自检**：写「文档行号校验」时第一版把 `.tsx` 当 `.ts` 匹配，误报 30 多条。**判据错的时候，工具会很自信地告诉你错误结论。**
3. **假模型能验逻辑，验不了体验**：`fakeCtx` 能证明轮次、事件、终态；证明不了「看起来快不快」。体验类验收必须真人看一次。
4. **`pnpm install` 在本机会卡**（851/851 后 `.bin` 不生成）：优先用已装在仓库里的依赖跑验证，不要把「重装依赖」当第一步。
5. **提交**：`type(0.2.0): 中文标题`；纯工具/文档改动单独一个 `chore(0.2.0)` 提交，不和功能混在一起。是否 push 由用户决定。
