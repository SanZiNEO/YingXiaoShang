# 产物怎么写

> 用在：动手写一份产物之前。
> 只有两种形态：**页面**和**题目集**。产物是附件，不替代回复。

## 0. 先判断要不要产物

**学生是不是明确要一份能带走的东西？**（「给我一份」「做成附件」「整理成一份」「精讲」「研究设计」「成长卡」）

不要 → **不要写附件**，在聊天里把话讲完。一句「为什么」、一次追问、一段点评，都不是产物。
要 → 再看是哪一种：

> **学生要不要在里面动手、动完手系统要不要接着算？**
> 要 → 题目集。不要 → 页面。

按这条，精讲案例、分析新闻、研究设计、BP 大纲、成长卡**都是页面**。目前只有出题是题目集。

## 1. 通用约束

1. **只写学生要的那一份**。一句闲聊、一句追问、一句「为什么」都不该变成附件。
2. **来源分离**：`sourceRefs` 只放课程/新闻/教材来源；学生能力证据走 `evidence_ids`，两者不混。
3. **不暴露内部 ID**：正文与标题里只写中文名称，不写 `kp_*`、`case_*`、`src_*`。
4. **事实与假设分离**：教学示例、虚构补全要显式标注「教学假设」。
5. **无原文不引用**：引用必须能回到原文段落；核实不了就写「资料不足」。
6. **写完就停**：写入后不再重写，也不在聊天里抄正文。

## 2. 页面（`write_page`）

参数：`title`（右栏文档头显示）、`html`（正文片段）、`sourceRefs`（可选）。

### 硬约束

- **单文件、内联样式**：不引外部 CSS / JS / 字体 / 图片链接，离线也要能看；
- **不写 `<script>`**：页面是给人读的，要交互就走题目集；
- **不写外框**：不要 `<html>`、`<head>`、`<body>`，只给正文片段（系统会放进沙箱 iframe）；
- **宽度**：按 320px 起排版，不许横向滚动；表格最多 3 列，多了拆开；
- **标题**：不要再写 `<h1>`，文档头已经有标题，正文从小标题开始；
- **配色**：浅底深字，正文对比度够，不要整页深色底。

### 推荐骨架

```html
<style>
  .doc { font-size: 15px; line-height: 1.8; color: #1f2328; }
  .doc h2 { font-size: 16px; margin: 22px 0 8px; }
  .doc p { margin: 8px 0; }
  .doc ul, .doc ol { margin: 8px 0; padding-left: 22px; }
  .doc li { margin: 4px 0; }
  .doc blockquote { margin: 10px 0; padding: 6px 12px; border-left: 3px solid #c8d0dc; background: #f7f8fa; color: #444; }
  .doc .take { margin: 12px 0; padding: 10px 12px; background: #f4f8ff; border-radius: 8px; }
  .doc table { border-collapse: collapse; width: 100%; font-size: 14px; }
  .doc th, .doc td { border: 1px solid #e3e6ea; padding: 6px 8px; text-align: left; }
</style>
<section class="doc">
  <h2>一句话结论</h2>
  <p>…</p>

  <h2>它是怎么起作用的</h2>
  <ol><li>…</li><li>…</li></ol>

  <h2>换个情境还成立吗</h2>
  <p>…</p>

  <h2>什么时候不成立</h2>
  <p>…</p>

  <div class="take">可迁移的一句：…</div>

  <h2>想一想</h2>
  <p>一个检查问题。</p>
</section>
```

**长内容分几次写**：第一次调用带上 `<style>` 和第一段 `<section>`，之后每次只写一段 `<section>`，系统按顺序拼接。不要整份重写，也不要一次只塞一句话。

### 常见错误

| 错法 | 为什么不行 |
|---|---|
| 通篇 `<div style="...">` 堆排版 | 内容一长就没人看得下去，先给结构再给样式 |
| 用 `<h1>` 再写一遍标题 | 右栏文档头已有标题，重复一次 |
| 引 CDN 上的字体/图标 | 离线打不开，等于没样式 |
| 拿 `<script>` 做折叠、做答题 | 沙箱禁脚本，脚本不会执行 |
| 一个概念写五个小节 | 讲清楚比排满重要 |

## 3. 题目集（`emit_question_set`）

参数：`content`（见下）、`title`、`markdown`（可选导出稿）、`sourceRefs`（可选）。

```json
{
  "intro": "这组题考什么，一句话",
  "questions": [
    {
      "id": "q1",
      "type": "单选 | 多选 | 判断 | 简答",
      "stem": "题干",
      "options": ["①②③④ 的文字", "…"],
      "answer": "B",
      "explanation": "交卷后展示：为什么是它，别的错在哪",
      "kpIds": ["消费者动机"],
      "difficulty": 2
    }
  ]
}
```

### 字段约束

- **`options` 只写选项文字**，不要带 `A.` `B.` 前缀——卡片会自己编号，写前缀会变成 `A. A. …`；
- **`type` 用中文**：单选 / 多选 / 判断 / 简答，不要写 `scenario_judgment` 这类内部枚举；
- **`kpIds` 填知识点中文名**，系统会翻成内部 id；一章里的题要落在本章知识点上；
- **`difficulty`**：1 基础（认得出）／2 应用（换情境仍能判断）／3 挑战（要在两种解释里选一个）；
- **`answer`**：选择题写字母（多选写 `AB`），判断题写 `对`/`错`，简答题写参考答案要点；
- **`explanation` 不写「略」**：交卷后学生只看这一段，它得能独立讲清；
- 一次 3–5 道，题目多就分 2–3 次调用；系统按题干去重合并，不要整份重写。

### 常见错误

| 错法 | 为什么不行 |
|---|---|
| 题干里带答案解析 | 交卷前会露答案 |
| `options` 写 `["A. ①②④", "B. ②③④"]` | 渲染成 `A. A. ①②④` |
| 五道题全考同一个知识点 | 看不出诊断价值，换三个层面 |
| 简答题没有参考答案 | 批改时无从对照 |

## 4. 落库与降级

- 页面存成 `.html`，题目集存成 `.docx`（另有 Markdown 导出稿）；
- 页面在右栏用沙箱 iframe 渲染：禁止脚本、禁止外链；题目集由题目卡渲染，答案交卷前折叠；
- 校验失败的那一份直接不生成，并告诉学生「可以让我重做一次」——不会留一张空卡片。
