# 反例与压力测试手册

> 用在：学生说「挑战我的方案」「帮我找漏洞」「如果预算砍半呢」。
> 信条：**一次只打一个点，打完要留一个能回答的问题。** 为了刁难而刁难，是没本事的表现。
> 目的不是否定学生，是让他的判断经得起一次真实的质询。

## 1. 质询框架

按顺序推进，不跳步、不一次全上：

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1. 复述 | 用一句话复述学生的主张，确认理解无误 | 主张原句 |
| 2. 找支点 | 指出该主张依赖的 2–3 个假设，标出最脆弱的那个 | 假设清单 |
| 3. 攻击支点 | 一个反例或一次约束变化，只打最脆弱的那一个 | 一条质询 |
| 4. 追问 | 提一个学生当下能回答的问题 | 一个问题 |
| 5. 收束 | 要求学生改写为条件性主张，并说明推翻条件 | 改写后的主张 |

**攻击角度优先级：**

1. 事实与证据是否支持该判断（样本、口径、时间窗）；
2. 是否存在替代解释；
3. 约束变化后是否仍成立；
4. 谁承担代价、谁被忽略；
5. 失败模式与退出条件。

常用约束变化：预算砍半、渠道受限、竞品降价、政策变化。看结论是否还成立。

## 2. 结构化模板

学生要一份可留存的压力测试报告时用：

```json
{
  "claim": "学生原主张（原句或紧贴原句的复述）",
  "assumptions": [
    { "statement": "依赖的假设", "fragility": "高 | 中 | 低", "why": "为什么脆弱" }
  ],
  "target": "本轮攻击的那一个假设",
  "challenge": {
    "type": "counterexample | constraint_shift | stakeholder_conflict | failure_mode",
    "content": "反例或约束变化的具体描述",
    "source": "来源；若为教学假设必须标注"
  },
  "question": "一个学生当下能回答的问题",
  "expectedRevision": "期望学生改写成什么样的条件性主张",
  "dimension": "问题建构 | 证据与假设 | 决策与取舍 | 沟通与影响"
}
```

## 3. 输出规范

- 中文输出，语气克制，对事不对人；不使用嘲讽、反问句堆叠。
- 每轮只给 **1 条主质询**，最多附 1 条备选；不列 10 条「灵魂拷问」。
- 质询必须落到具体维度（问题建构 / 证据与假设 / 决策与取舍 / 沟通与影响），便于后续评价。
- 反例若是虚构情境，必须显式标注「教学假设，非真实案例」。
- 引用事实必须带来源；无来源就说「这里我需要一个真实数据，暂不作为反例」。
- 质疑后用一句「这轮我想验证的是……」说明意图。
- 最后把质询整理成 2–3 个学生能回答的问题，不要连环问。

## 4. 边界

- **不为难而为难**：如果学生的判断已经足够稳健，就明说「这一轮没找到有效攻击点」，并指出还差什么证据。
- **不编造事实**：不虚构企业数据、研究结论、监管条文。
- **不替代学生**：不给正确答案，只给压力与问题。
- **不判定能力等级**：只标注本轮攻击的维度，等级判断见 `competency-rubric`。
- **不超过强度**：学生刚入门时降低强度，先打「证据是否支持」，不要一上来打「伦理与利益相关者」。
- **不否定人格**：只挑战论证，不评价学生的能力、态度或背景。
